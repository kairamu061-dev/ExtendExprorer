# BUG-051: 別のフォルダを開いても、前のフォルダのスクロール位置のまま開く

- **State**: Fixed
- **Reported**: 2026-10-24（検証セッション・§5。**依頼書に無い発見**）
- **Area**: `UI/FileListView.OnEntriesReset`

## Summary

フォルダを移動すると、**新しいフォルダが「前のフォルダと同じ行番号」まで
スクロールした状態で開く。**行数が足りないフォルダを挟むと 0 に戻る。

## Reproduction

1. `H\sub01` を**先頭行 45** までスクロールする
2. アドレス欄で `B`（2001 行）へ移動する
3. → **先頭行 45 のまま開く**（先頭から見えない）

## Expected

**新しいフォルダは先頭から。**

- `docs/.../spec.md` では「スクロール位置の復元」は**未対応**＝先頭から、が前提
- **Windows のエクスプローラーも先頭から開く**

## Measured / Inferred

| | 測った（根拠） | 推測（何が分かれば決まるか） |
|---|---|---|
| 症状 | ★ **検証セッションが実測**（2026-10-24）。45 → `B` → `W2` と移っても先頭行 45 のまま | — |
| 原因 | ★ **ソースから確定。**`LVM_SETITEMCOUNT` は**スクロール位置を戻さない。**戻す処理をどこにも書いていなかった | — |
| 影響 | ★ **新旧で完全に同じ**（`fc537db` / `46cd82c` 両方で先頭行 45）。**今回の変更による後退ではない** | いつから入っていたかは追っていない |

## Fix

`OnEntriesReset` で、**選択を引き継がないとき（＝別のフォルダ）だけ**
`LVM_ENSUREVISIBLE` で 0 行目を見せる。

**同じフォルダの読み直し・並べ替え（`keepSelection: true`）では戻さない**——
見ている場所から飛ばされる方が困る。

**`LVM_SETITEMCOUNT` のフラグ（`LVSICF_NOSCROLL`）は触っていない。**
あちらを変えると再描画の挙動まで変わり、BUG-037（描き残し）の家族に触れる。
**位置を戻すことだけを、別の 1 行でやる。**
