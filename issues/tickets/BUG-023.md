# BUG-023: ペインの帯が、幅の変わったときに描き直されない（分割ボタンの跡が並ぶ／消える）

- **State**: Fixed
- **Reported**: 2026-08-27
- **Area**: win32-migration / address-bar / `src/ExtendExprorer.Win32/UI/PaneBandView.cs`

## Summary

ペインの帯（ナビ＋パンくず）の幅が変わると、右端に寄せて描いている分割ボタンが
**古い位置に残る**（広げたとき）か、**1 つも描かれない**（狭めたとき）。
クリックは正しい位置で効くので、壊れているのは見た目だけ。

**ペインの仕切りのドラッグという日常操作で起きる。**

## Reproduction

1. ウィンドウ幅 1200 で起動する
2. 1400 に広げる → 分割ボタンが **3 組**見える（正しいのは右端の 1 組だけ）
3. 1000 に狭める → 分割ボタンが **1 組も描かれない**

| 操作 | 分割ボタンの見つかった位置（画像 x） |
|---|---|
| 1200 → 1400 | 1041-1078、1141-1178、1341-1378（正しいのは最後だけ） |
| → 1000 | 無し |
| → 1200 | 1141-1178（正しい） |

2 ペインにして仕切りを左右に振る、ウィンドウを最大化する、`--panes=4` で
縦の仕切りを動かす、のいずれでも再現する。

## Expected

幅が変わっても、帯は常に現在の幅に合わせて描かれること。

## Cause

**大きさが変わったときに、帯の全体を無効化していなかった。**

ウィンドウを広げると、既定では**新しく現れた部分だけ**が無効化される。
帯は `WM_PAINT` で全面を塗り直しているが、描画は更新領域にクリップされるため、
既に描いてあった部分の古い絵はそのまま残る。狭めたときは新しく現れる部分が無いので
`WM_PAINT` 自体が来ず、古い絵が残ったまま切り取られる。

左端に寄せて描くもの（戻る・進む・上へ）で問題が出なかったのは、
幅が変わっても位置が動かないため。**右端に寄せて描くものだけが露呈した。**

## Fix

ウィンドウクラスに `CS_HREDRAW | CS_VREDRAW` を付けた。大きさが変わると
OS が窓の全体を無効化するようになる。

同じ作りの自前描画（`ChromeBar`・`TabStripView`）にも同時に付けた。
どちらも今は左端に寄せて描いているため表面化していなかったが、条件は同じ。

- **Fix commit**: `7eba9b7`

## Notes

確認側は、この不具合を踏まないよう「起動して 1 回だけ位置を決め、以後リサイズしない」
手順に切り替えて他の項目を判定している。他の判定は汚染されていない。
