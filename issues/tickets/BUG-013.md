# BUG-013: 正式(Native AOT)ビルドが起動直後にクラッシュする

- **State**: Fixed（原因を特定して修正。AOT 実機での再確認待ち）
- **Reported**: 2026-08-04
- **Area**: build / aot（`PanelSplitter`）

## Summary

成果物 `ExtendExprorer-win-x64`（Native AOT）が、起動してウィンドウが表示された数秒後（6〜8 秒）に
100% クラッシュする。JIT ビルド（`ExtendExprorer-win-x64-jit`）は同じ操作で完全に安定しており、AOT 固有。

## Reproduction

1. `ExtendExprorer-win-x64`（AOT）を展開して起動する
2. ウィンドウは表示されるが、6〜8 秒でプロセスが消滅する（3 回中 3 回）

- Application Error: `Faulting module name: Microsoft.UI.Xaml.dll` / `Exception code: 0xc000027b`（STOWED_EXCEPTION）
- WER: `P7: 80004002`（`E_NOINTERFACE`）
- クラッシュダンプ: `%LOCALAPPDATA%\CrashDumps\ExtendExprorer.exe.*.dmp`

## Expected

AOT ビルドでも JIT と同じく安定して動作する。

## Cause

**`PanelSplitter` が `partial` でなかった。**

WinRT 型（`Grid`）を継承したクラスは、CsWinRT のソース生成が COM の vtable（CCW）を出力できるよう
`partial` でなければならない。付け忘れると JIT では動くが、Native AOT では XAML フレームワークからの
QueryInterface が `E_NOINTERFACE` で失敗する。WER の `P7: 80004002` はまさに `E_NOINTERFACE` で、
`Microsoft.UI.Xaml.dll` の STOWED_EXCEPTION（`0xc000027b`）として現れていた。

同じ `Grid` 派生でも、ペイン分割の `SplitterBar` は最初から `partial` だったため影響を受けていない。
`.xaml.cs` を持つ型は XAML の生成コードが `partial` を付けるので、素の C# で書いた
`PanelSplitter` だけが唯一の抜けだった。

### 特定の経緯

| 根拠 | 内容 |
|------|------|
| 実機バイセクト（2026-08-07） | `aot-bisect-a` 3/3 起動 → `aot-bisect-b` 3/3 クラッシュ。`PanelSplitter` が入るのが b |
| main も同一署名 | `1d34058` も b と同じ fault offset `0x39ce55`。XAML 生成→コード生成の変更では直らない＝**生成場所ではなく型そのもの**の問題 |
| **ビルドログ** | `warning CsWinRT1028: Class 'PanelSplitter' implements WinRT interfaces but ...` が **aot・jit 両ジョブで出ていた** |

> 検証者の第一容疑だったベクター化は、b の時点で既に落ちるため無関係と確定した。

### 見落とした理由

コンパイラは CsWinRT1028 で正しく警告していたが、**警告のままだったため確認依頼書に
「コンパイル警告なし」と誤って記載し、実機検証まで気付けなかった**。
再発防止として CsWinRT1028 を `WarningsAsErrors` に指定し、ビルドが失敗するようにした。

## Fix

1. `PanelSplitter` を `internal sealed partial class` にした（本体の修正）
2. `ExtendExprorer.csproj` で `CsWinRT1028` をエラーに昇格（再発防止）

- **Fix commit**: 本チケット更新と同じコミット
- 先行して入れた 2 つ（アイコンキャッシュの再入回避 `AlreadyResolvedAsync` / `PanelSplitter` の
  コード生成化）は**このクラッシュの原因ではなかった**が、どちらも単独で妥当なのでそのまま残す。
  XAML への再宣言は AOT の起動が確認できてから戻す（1 回の検証で 2 つ変えない）。

## Notes

- 2026-07-30 の「初回起動で 1 回だけ静かに終了」は、`PanelSplitter` 導入前なので別事象の可能性が高い。
- JIT で確認済みの各項目（BUG-010/011/012・自然順・差分更新・サイズ感）は、**AOT でも再確認**が必要。
- バイセクト用タグ `aot-bisect-a/b/c` は役目を終えたが、履歴として残す。
