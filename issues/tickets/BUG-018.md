# BUG-018: 一覧で頭文字キーを打っても項目に飛ばない

- **State**: Closed
- **Reported**: 2026-08-15
- **Area**: win32-migration / file-list（`src/ExtendExprorer.Win32/UI/FileListView.cs`）

## Summary

一覧にフォーカスがある状態で文字キーを打っても、その頭文字の項目へ選択が移動しない
（矢印キーによる移動は動作する）。

## Reproduction

1. `banana.log` を含むフォルダを開き、一覧にフォーカスを与える
2. `b` を打つ
3. 観測: 選択が動かない

## Expected

`banana.log` へ選択が移動する（エクスプローラーと同じ）。

## Cause

オーナーデータの一覧は項目の中身を知らないため、頭文字検索は `LVN_ODFINDITEM` を
アプリ側で処理して行番号を返す必要がある。処理自体は実装していたが、
**`LVFI_STRING` が立っていることを必須にしていた**。

`LVFINDINFO` のフラグは版によって異なり、Windows Vista 以降は `LVFI_SUBSTRING` が使われる
ことがある。`LVFI_STRING` が無いものを弾いていたため、常に「見つからない（-1）」を返していた。

## Fix

フラグでの足切りをやめ、**探す文字列が渡されていれば前方一致で探す**ようにした。
見つからなければ先頭へ回り込むのは従来どおり。

- **Fix commit**: c2bf4a1

## Notes

フラグの組み合わせは版に依存するため、今後も条件を増やさない方針とする。
