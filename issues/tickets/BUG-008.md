# BUG-008: ファイル操作の結果が一覧に反映されない（D&D 移動後に表示が変わらない）

- **State**: Fixed
- **Reported**: 2026-07-26
- **Area**: file-list / drag-drop（`src/ExtendExprorer/ViewModels/TabViewModel.cs`）

## Summary

ドラッグ＆ドロップでファイル・フォルダを移動すると、ディスク上は正しく移動されるが一覧の表示は変化しない。
移動元ペインからも項目が消えず、移動先ペインにも現れない。手動で移動し直すまで古い内容が表示され続ける。

## Reproduction

1. 2 ペインに分割し、それぞれ別のフォルダを表示する
2. 左ペインの項目を右ペインへドラッグ＆ドロップする
3. 実際のファイルは移動しているのに、左右どちらの一覧も表示が変わらない

## Expected

シェル経由のファイル操作（D&D の移動／コピー、貼り付け、削除、外部アプリからの変更）の結果が、
そのフォルダを表示しているすべてのペインの一覧に自動で反映される。

## Cause

一覧の再読込は `RefreshAsync` の明示呼び出しにのみ依存していた。リネーム（`CommitRename`）だけが呼んでおり、
D&D・貼り付け・削除は呼んでいない。加えて `IFileOperation` は非同期に完了するため、操作直後に一度
再読込しても間に合わないことがある。移動元ペインは自分が操作の当事者ですらないため、そもそも通知がない。

## Fix

`TabViewModel` に `FileSystemWatcher` による自動再読込を追加した。

- 表示中フォルダ（サブフォルダは監視しない）の作成・削除・リネーム・属性変更を監視する。
- 変更通知はバースト状態で届くため 400ms のデバウンスをかけ、UI スレッド（`DispatcherQueue`）へ marshal してから `RefreshAsync`。
- リネーム編集中に一覧が作り直されると編集ボックスが消えるため、`FileListView` が
  `SuspendAutoRefresh()` / `ResumeAutoRefresh()` で抑制できるようにした（抑制中に来た変更は解除時にまとめて反映）。
- `TabViewModel` を `IDisposable` にし、タブを閉じるとき（`MainViewModel.CloseTab`）に watcher を破棄する。

- **Fix commit**: `b499e61`

## Notes

- 副次的に、貼り付け・削除・外部アプリによる変更も自動で一覧に反映されるようになった。
- 素朴に再読込すると選択が毎回外れてしまうため、`FileListView` 側で選択項目を名前で覚えて
  再読込後に復元している（`5f97ded`）。あわせて `TabViewModel` は内容が同じ `EntryViewModel` を
  使い回し、アイコンの再取得によるちらつきを防ぐ。
- 監視できないパス（権限なし・ネットワーク断など）では例外を握りつぶし、自動更新なしで動作を続ける。

> 2026-07-27 実機検証: アプリ内の貼り付け 0.51 秒・削除 0.25 秒・外部アプリでの作成 0.56 秒で一覧に反映され、
> 選択も維持されることを確認。`%LOCALAPPDATA%\ExtendExprorer` を 60 秒表示しても session.json の再書き込みは 0 回
> （保存ループ無し）。権限の無いパス・存在しない UNC でもクラッシュしない。
> **D&D そのもの（E-44）は合成ドラッグを WinUI が受け付けないため自動検証できず、実機目視が残っている。**
> 同じ監視経路で反映されるため見込みは高いが、目視確認が取れるまで Closed にしない。
