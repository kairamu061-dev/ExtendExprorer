# win32-migration 設計

## 技術選定

| 技術 | 用途 | 理由 |
|------|------|------|
| C# / .NET 8 **Native AOT** | 実装言語 | 既存のシェル相互運用とロジックをそのまま持ち込める。ランタイムを積まないので実確保 6.8MB（実測） |
| 素の Win32（`user32` / `comctl32` / `shell32`） | UI | 目標 30MB を満たす唯一の選択肢。OS のコントロールをそのまま使うので外観がエクスプローラーと同じになる |
| `LibraryImport` ＋ `GeneratedComInterface` | 相互運用 | AOT 互換。現行でも同じ方式を使っており実績がある |

**WinForms を採らない理由**: 実測で素の Win32 より +26MB（52.0MB）。Native AOT 非対応のため
JIT ランタイムが戻るのが主因で、目標 30MB に届かない。

## アーキテクチャ

```
Program（メッセージループ）
└ MainWindow（親ウィンドウ・WM_SIZE でレイアウト）
  ├ FolderTree      … SysTreeView32
  ├ PanelSplitter   … 自前の細いウィンドウ（現行と同じ考え方）
  └ PaneHost        … ペイン分割の木（現行の LayoutNode をそのまま移植）
    └ Pane × N
      ├ TabStrip    … 自前描画（折り返しが要るので OS のタブは使わない）
      ├ Toolbar     … 自前描画のボタン群（戻る/進む/上へ・分割）
      ├ AddressBar  … パンくず（自前描画）
      └ FileList    … SysListView32（LVS_REPORT | LVS_OWNERDATA）
```

- **ViewModel 層は残す。**ただし `Visibility` / `ImageSource` など XAML の型への依存を外し、
  `INotifyPropertyChanged` の代わりに素の C# イベントで View に通知する
  （バインドが無いので、View 側は通知を受けて `InvalidateRect` / `LVM_UPDATE` を出す）
- **1 ウィンドウ = 1 メッセージループ。** ペイン・タブは子ウィンドウか自前描画で、
  スレッドは 1 本のまま（現行と同じ）

## メモリに効く設計判断（ここが移行の主目的）

| 項目 | 現行（WinUI 3） | 新実装 |
|------|----------------|--------|
| アイコン | 1 枚ずつ `WriteableBitmap` に変換して保持 | **OS のシステムイメージリストを借り、項目ごとにインデックス（int）だけ持つ** |
| 一覧の行 | 行ごとに `EntryViewModel`（`ObservableObject`） | 行ごとに軽い構造体／配列。表示は `LVN_GETDISPINFO` で**見えている行だけ**組み立てる |
| 非アクティブタブ | 一覧データを全件保持 | **パスと最小限の状態だけ**。一覧は表示時に作る（BUG-016 の対処も兼ねる） |

## BUG-016（タブ追加のコスト）への対処

実測（2026-08-13）で原因が確定している。

- タブ数には比例しない（3 枚 1.27 秒 / 30 枚 0.89 秒）
- **開いているフォルダの項目数に比例する**（空 0.24 秒 / ホーム 1.37 秒）

したがって犯人は**タブ追加のたびに走るフォルダ列挙と一覧の生成**。新実装では次の 2 点で構造的に解消する。

1. 列挙はワーカースレッドで行い、UI スレッドは結果の配列を受け取るだけにする
2. 行の表示物（文字列・アイコン番号）は `LVN_GETDISPINFO` で**見えている行だけ**作る。
   1 万件のフォルダでも、作るのは画面に出ている数十行分だけ

> **現行の WinUI 3 版では直さない。**直しても捨てるコードであり、移行後は上の設計で消えるため。
> 移行が終わるまでの回避策は「＋ を連打しない」（1 回ずつ待てば 40 枚まで到達できることを確認済み）。

## 引き継ぐふるまいの規則（実装は変わっても仕様は同じ）

- 一覧の追随は**差分更新**（追加＝末尾／リネーム＝位置固定／削除＝その行だけ）
- 監視は項目の増減・改名のみ（サイズ・更新日時は見ない）
- 名前のソートは `StrCmpLogicalW`（自然順）
- リネームは「間を空けた 2 回目のクリック」で開始し、拡張子を除く部分を選択。Tab で次の行へ
- ファイル操作はすべてシェルに委譲（`IFileOperation`）
- session は現行の JSON をそのまま読める形にする（バージョン互換）
