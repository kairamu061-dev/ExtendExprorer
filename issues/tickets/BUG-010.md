# BUG-010: 一覧のフォルダアイコンが使用中にグリフへ劣化し、再起動まで戻らない

- **State**: Fixed
- **Reported**: 2026-07-30
- **Area**: shell-icons / file-list（`src/ExtendExprorer/Services/ShellIconCache.cs`）

## Summary

長時間・多操作のセッション後、一覧（ファイルリスト）のフォルダアイコンが黄色いシェルアイコンではなく
細い輪郭のグリフ（フォールバック表示）に変わり、以後どのフォルダへ移動しても戻らない。
アプリを再起動すると正常に戻る。左のツリーは劣化しない。

## Reproduction

1. アプリを起動する（この時点では一覧のフォルダアイコンは黄色いシェルアイコン）
2. リネーム・貼り付け・タブ操作・自動更新を含む操作を長時間続ける
3. 一覧のフォルダアイコンが輪郭のみのグリフに変わる（`C:\` でもホームでも同様）
4. 別フォルダへ移動しても、同じフォルダを再読込しても戻らない
5. 左のツリーのアイコンは黄色いまま。アプリを再起動すると一覧も黄色に戻る

## Expected

一時的にシェルアイコンの取得へ失敗しても、次の取得で回復する（再起動を要しない）。

## Cause

`ShellIconCache` が **失敗した `Task` もキャッシュに残していた**。

```csharp
// 修正前
if (!Cache.TryGetValue(key, out var task))
{
    task = LoadAsync(...);   // 失敗すると null を返す Task
    Cache[key] = task;       // その Task が永久に残る
}
```

フォルダの汎用アイコンはキー `<dir>` を全フォルダで共有しているため、**一度でも取得に失敗すると
以後すべてのフォルダが「アイコン無し」になる**。`EntryViewModel` は移動・再読込のたびに作り直されるので、
新しい行はすべて失敗済みの `Task` を受け取りフォールバックのグリフを表示する。

左のツリーが劣化しないのは、`FolderNodeViewModel` が作り直されず、劣化前に取得した
`ImageSource` を保持し続けるため。再起動で復帰するのは、キャッシュがプロセス内の静的辞書だから。

失敗の引き金（`SHGetFileInfoW` が一時的に失敗する条件）は特定できていないが、**一度の失敗が
恒久化する設計そのもの**が本質的な原因。

## Fix

キャッシュを「成功したアイコンだけを保持する」構造に変更した。

- 解決済み（`Resolved`）と取得中（`InFlight`）を分け、**失敗した取得は記録しない**
  → 次の要求で自動的に再試行される（＝一時的な失敗から自己回復する）
- 取得はワーカースレッド内で 1 回だけ即リトライする（一時的な失敗の多くはこれで吸収できる）

- **Fix commit**: `d93f3be`

## Notes

- 過去の BUG-002（リーク）と同系統かを疑う報告だったが、検証時の GDI オブジェクト数（59 固定）・
  ハンドル数（約 1150 で安定）からリークの兆候はなく、キャッシュの設計に起因するものだった。
- コードレビュー（`tmp/コードレビュー_2026-07-29.md` の 4 項）では、この失敗キャッシュを
  「無限リトライしない意図どおりの設計」と評価していたが、実際にはこの挙動が不具合の原因だった。
  リトライ抑止は `EntryViewModel._iconRequested`（VM 単位）で足りており、プロセス全体で
  共有するキャッシュに失敗を残す必要はない。
- 引き金の特定は未了。再発した場合に切り分けられるよう、失敗が恒久化しないことを先に確保した。
