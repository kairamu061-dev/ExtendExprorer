# BUG-036: 左右に分割した状態でフォルダビューを開閉すると、右のペインの表示が乱れる

- **State**: Fixed（実機確認待ち）
- **Reported**: 2026-09-18
- **Area**: win32-migration / layout / `src/ExtendExprorer.Win32/UI/MainWindow.cs`

## Summary

左右に分割した状態で、左のフォルダビュー（ツリー）を「◀」「▶」で開閉すると、
**右のペインの表示が乱れる。**

## Cause

**並べている最中に `LayoutChildren` へ戻ってきていた。**

1. ツリーを開閉するとペインの幅が変わる
2. `PaneView.SetBounds` が **タブ帯 → ナビ帯 → 一覧** の順に置く
3. 1 つ目のタブ帯で幅が変わると**折り返しの行数が変わり**、
   `TabStrip.SetBounds` の中から `HeightChanged` が上がる
4. それが `PaneView.LayoutChanged` → `PaneHost.LayoutChanged` → `LayoutChildren` と
   **元の関数まで戻ってくる**。戻ってきた側は正しく並べ直す
5. **戻ったあと、外側が 2 つ目と 3 つ目を書き戻す**——
   使うのは**行数が変わる前に計算した矩形**

[BUG-031](./BUG-031.md) と同じ「状態を作りきる前に知らせた」形。
あちらはタブ帯の中の話で、今回はその 1 つ上の層。

## Fix

**再入は受け付けず、印だけ立てて戻る。**外側が書き終わってから、もう一度並べ直す。

行数が 2 つの値を行き来する幅があると理屈の上では終わらないので、**上限（4 回）**を置き、
そこまでいったら `--diag` に残す。**止まらないより、止まったことが分かる方がよい。**

- **Commit**: `e251e8f`

## Notes

- **通知は「状態を作りきってから」出すのが原則**（BUG-031 の学び）だが、
  出す側が他所の部品だと直せないことがある。**受ける側で再入を畳む**のがもう一つの手
- 1 ペインでは起きない。**分割していて、かつ幅の変化が折り返しの行数を変えるとき**だけ
