# folder-tree 仕様

## 機能一覧

| # | 機能名 | 説明 |
|---|--------|------|
| 1 | ツリー表示 | ウィンドウ左側のパネル（既定幅 240px・**境界のドラッグで変更可能**）。**ルートはシェルの名前空間の根**（ホーム / ギャラリー / OneDrive / デスクトップ / ダウンロード / ドキュメント / ピクチャ / ミュージック / ビデオ / PC / ネットワーク など）。並びは**シェルに決めさせる**（`IShellFolder.CompareIDs`）<br>**2026-09-13 変更**: それまでは「ホーム」＋準備完了ドライブだった |
| 1b | **根に出さないもの**（2026-09-14 追加） | デスクトップの子ではあるが、エクスプローラーのナビゲーションウィンドウが出していないものを**根でだけ**外す。**ごみ箱 / コントロール パネル / ライブラリ / 利用者のプロファイルフォルダ**の 4 つ。<br>**中身が開けなくなるわけではない**（別の道からは辿れる）。判定は**解析名**（`::{CLSID}` と実パス）で行う——表示名は言語で変わるため |
| 1c | **隠し・システムも出す**（2026-09-14 明記） | 一覧（ファイルシステムを直接読む側）が出して薄色にしているので、ツリーも合わせる。片方だけ隠すと**同じアプリの中で食い違う** |
| 2 | 遅延展開 | シェブロンクリックで初めて子を列挙して子ノードを作る。ファイルは表示しない。2 回目以降の展開は再列挙しない |
| 3 | クリック移動 | ノード本体のクリック（Invoke）でアクティブペインのアクティブタブが該当パスへ移動（履歴に積む＝戻れる）。**ただし移動できるのはファイルシステム上の実体があるノードだけ**（下記 3b） |
| 3b | **仮想フォルダの扱い**（2026-09-13 追加） | ファイルシステム上のパスを持たないノードは、**クリックしても移動せず展開する**。<br>**例外は `PC`**——中身（ドライブと容量）を一覧に出せるので**移動する**（file-list 仕様の「PC の一覧」）。`ネットワーク` `ごみ箱` は展開のみ |
| 4 | 折りたたみ | ヘッダの「◀」でパネルを幅 28px のストリップへ折りたたみ。「▶」で**ドラッグで決めた幅に**再展開。状態はセッションに保存する |
| 6 | **幅調整**（2026-07-30 追加） | ツリーと一覧の境界（5px のバー）をドラッグしてツリーの幅を変える。120〜600px の範囲で、右の一覧には常に 240px 以上を残す。幅はセッションに保存し、次回起動時に復元する |
| 5 | 薄灰色表示 | 隠し・システム属性のフォルダは Opacity 0.55（file-list と同一ルール） |

## 画面・操作フロー

1. 起動 → 左側にツリー（エクスプローラーのナビゲーションウィンドウと同じ根）が表示される
2. ノードのシェブロンをクリック → サブフォルダが遅延読込されて展開
3. ノード名をクリック → アクティブペインのアクティブタブがそのフォルダへ移動
   （`ネットワーク` などパスを持たないノードは、移動せずその場で展開する。
   **`PC` だけは「ドライブの一覧」へ移動する**）
4. ヘッダ「◀」をクリック → パネルが細いストリップに折りたたまれ、一覧領域が広がる
5. ツリーと一覧の境界にカーソルを合わせる → 左右矢印カーソルに変わる
6. そのままドラッグ → ツリーの幅が追従し、離した位置で確定する（次回起動時もその幅で開く）

## 各画面 / 状態の詳細

### ツリーパネル（展開時）

- **表示内容**: ヘッダ（「フォルダー」ラベル＋◀ボタン）、TreeView（フォルダアイコン＋フォルダ名）、右端に幅調整バー（5px）
- **操作**: シェブロン=展開/折りたたみ、ノード Invoke=移動、◀=パネル折りたたみ、右端バーのドラッグ=幅調整
- **遷移先**: アクティブタブのフォルダ移動（ペイン構成は変わらない）

### ツリーパネル（折りたたみ時）

- **表示内容**: 幅 28px のストリップに「▶」ボタンのみ（**幅調整バーは隠す**）
- **操作**: ▶=パネル再展開（折りたたむ前の幅に戻る）
- **遷移先**: なし

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| アクセス不可フォルダを展開 | 子ノード 0 件として展開（エラーダイアログは出さない）。シェブロンは消える |
| 展開後にフォルダが削除されていた | 同上（列挙失敗を空扱い） |
| ノード Invoke 先が存在しない | タブ側の既存エラー処理（「フォルダが見つかりません」表示）に委ねる |
| 幅を極端に広げる / 狭める | 120〜600px にクランプ。加えてウィンドウ幅から右の一覧に 240px を残せる位置で止まる |
| 保存された幅が現在のウィンドウに収まらない | クランプ範囲内なのでそのまま復元する（一覧が狭くなるだけ。ドラッグで戻せる） |
| **パスを持たないノードをクリック** | **移動せず展開する。**エラーにはしない（`ネットワーク` `ごみ箱` など） |
| **`PC` をクリック** | 一覧が「ドライブの一覧」になる。ツリー側も展開する |
| **パスは取れるが開けないノード** | 移動しない。`SFGAO_FILESYSTEM` が立っていても `Directory.Exists` が false なものがある（コントロールパネルの一部など）ので、**両方を見てから**移動する |
| **ネットワークの列挙が返ってこない** | ツリーは固まらない（列挙は専用スレッドで回す）。そのノードのシェブロンが開かないまま待つ |
| シェルの根が読めない | ツリーは空のまま。落ちない・ダイアログも出さない |
| 並び順が決められない（`CompareIDs` が失敗） | その 2 つの順は変えない（列挙の順のまま）。落ちない |

## 未対応ケース

- **`ネットワーク` `ごみ箱` を一覧ペインで開くこと。**ツリーでは展開できるが、
  クリックしても右の一覧には出ない。一覧ペインはパス文字列でフォルダを開く作り
  （オーナーデータ・自動更新・D&D・ソートがすべてパス前提）なので、
  ここに手を入れるのは別の話とした（2026-09-13 ユーザ判断）。
  **`PC` だけは中身が全部「実パスを持つ行」なので例外的に開ける**ようにした
- **クイックアクセスのピン留めを根に並べること。**エクスプローラーのナビゲーション
  ウィンドウは、デスクトップの子の列挙結果**そのものではなく、その上で組み立てられている**。
  ピン留めは別に足されているもので、列挙しただけでは出てこない（2026-09-14 実測）
- タブ移動へのツリーの追従（選択・自動展開）
- ツリーの手動更新（リフレッシュ）・ファイルシステム変更の監視
- ツリー幅のドラッグ変更（固定 240px）
- 折りたたみ状態のセッション保存（session サブ項目で扱う可能性あり）
