# BUG-038: `.exe` が並ぶフォルダへの移動が極端に遅い（アイコンを描くたびに引き直している）

- **State**: Open
- **Reported**: 2026-09-28
- **Area**: shell-icons / file-list（`Services/ShellImageList.cs`・`UI/FileListView.cs`）

## Summary

`D:\インストーラー` のような **`.exe` が多数入ったフォルダ**を開くと、遷移が極端に遅い。
`.exe` は**ファイルごとに固有のアイコンを持つ**ので実パスで `SHGetFileInfoW` を呼んでいるが、
その結果を**覚えていなかった**——しかも呼んでいるのは **`LVN_GETDISPINFO`（オーナーデータ）**で、
**描くたびに同じ行をもう一度聞かれる。**

## Reproduction

1. `.exe` が数十〜数百件入ったフォルダ（インストーラーの置き場など）へ移動する
2. 一覧が出るまで待たされる
3. スクロールしても、そのたびに引っかかる

利用者の報告（2026-09-28）:

> 以下のフォルダを開いたときめちゃくちゃ遷移が遅かったんだけどアイコンとかのせい？
> `D:\インストーラー`

## Expected

- 一覧が出るまでの待ちが、ファイル数に対して極端に増えないこと
- **一度出したフォルダを再描画・スクロールするときは、ディスクを読み直さないこと**

## Cause

`ShellImageList.IndexOf` の `PerFileExtensions`（`.exe` / `.lnk` / `.ico` …）の枝だけが
**実パスで `SHGetFileInfoW`** を呼ぶ。ここが 2 つの意味で効いていた。

1. **控えが無い。**`ByExtension` は拡張子の枝だけ、`ByPath` は `IndexOfPath`（ツリー・ドライブ）
   専用で、**この枝はどちらも通らない。**毎回ディスクを読む
2. **呼び出し元が `LVN_GETDISPINFO`**（`UI/FileListView.cs:1037`）。
   オーナーデータなので、**スクロール・選択・再描画のたびに同じ行を聞かれる。**
   しかも UI スレッドの `WM_PAINT` の中なので、**終わるまで窓が描けない**

`.exe` 1 件あたりの費用は「PE を開いて資源を読む」だけではない。
**常駐のウイルス対策が開かれた `.exe` を走査する**ので、そこが乗ると 1 件で数十 ms になりうる。
`D:` がどういう装置かも最初は見えなかったが、**利用者の追加報告（2026-09-28）で決まった。**

| 追加情報 | 読めること |
|---|---|
| **遷移が遅いのは初回だけ。二回目は速い** | **OS 側が覚えている。**`SHGetFileInfoW` の 2 回目はシェルの絵の控えから返る |
| **スクロールも遅くない** | 同じ理由。**同じ行を聞き直しても、2 回目以降は安い** |
| **`D:` は内蔵 SSD** | **媒体は速い。**残る費用は **PE の読み取り**と**常駐の走査** |

> **★ これで第 1 段（控え）は狙いを外していたと分かった。**
> **二回目が速いのは OS のおかげで、こちらの控えのおかげではない。**
> 直すべきは**初回**で、**避けられない仕事を UI スレッドから外す**しかない。

## Fix

**2 段に分けた。両方入れた。**

**体感に効くのは第 2 段。**第 1 段は狙いを外していた（下記）。

### 第 1 段（入れた。ただし**狙いは外していた**）

- **実パスで引いた結果を覚える**（`ByFile`。パスをキーに、**取れなかったときの落とし先も**）。
  取れないときを覚えないと、読めないファイル（ロック中・検疫済み）が
  **描画のたびにディスクを叩く**ことになり、うまくいく場合より重くなる
- **同じフォルダを読み直したときだけ控えを捨てる**（差し替えたファイルの絵が古いまま残らない）。
  別のフォルダへ移るときは捨てない（行って戻るのが速い方が嬉しい）
- 上限 **2048 件**（メモリ要件があるので無制限には持たない）
- **計測を足した。**下記

```
[icon] 引くスレッド開始 CoInitializeEx=0x00000000
[list] 読み込み結果 D:\インストーラー 件数=312 列挙=95ms エラー=なし
[icon] D:\インストーラー 移動したので 裏で引いた=294 件 合計=4980ms 最長=61ms（...） 覚えていた=312 件 控え=312 件
```

- **`列挙=` と `[icon]` の合計を並べる**ので、**アイコンとそれ以外の内訳**が読める
- **`最長=` と名前**が出るので、「1 件だけ極端に遅い」と「全部が少し遅い」を分けられる
- **`覚えていた=`** が控えの効き目。ただし**利用者の追加報告のとおり、2 回目が速いのは OS のおかげ**なので、
  ここが効いても体感は変わらない

> **計測の書き出しは「移動したとき」**にしている。読み込みの直後に書こうとすると **0 件**になる——
> 第 2 段では**引くのが裏**なので、なおさら読み込みを抜けたあとに積まれる。
> 「0 件」と書いてしまうと、**速かったのか数えていなかったのか**が区別できない。
>
> **`合計=` は「裏で使った時間」で、利用者が待った時間ではない。**
> 第 2 段のあとは **`合計=` が大きくても一覧はすぐ出る**——そこが狙い。

- **Fix commit**: 第 1 段 `0cc489a` / **第 2 段 `6de55a0`**

### 第 2 段（入れた。**ここが本体**）

**`LVN_GETDISPINFO` からシェルを呼ぶのをやめた。**
その場では**拡張子の既定アイコンを即返し**、実パスは**専用スレッドで引く**
（MTA。`ShellNamespace` と同じ作り。ポンプの無い STA は行き詰まりの罠）。
引けたら `Resolved` を 1 回上げ、**一覧が自分を無効化する**。

- **どの行が変わったかは追わない。**`LVN_GETDISPINFO` が控えから取り直すので、
  無効化すればそれで足りる
- **結果は UI スレッドへ戻してから `ByFile` へ入れる。**辞書を 2 つのスレッドで触らない
- **投げるのは取り込みごとに 1 回だけ。**1 件ごとに投げると、
  数百件のフォルダで UI の行列が結果で埋まる
- 順番待ちは **4096** で打ち止め。捨てても**次に描かれるときにまた頼まれる**ので取りこぼさない

**これで「絵が出そろうまでの時間」は縮まらない。**縮まるのは
**一覧が出るまでの時間**——最初は既定のアイコンで並び、絵は後から差し替わる
（エクスプローラーと同じ見え方）。

**先に第 1 段をやったのは順番を間違えた。**費用の内訳を測る前に控えを足したが、
**利用者の追加報告 3 行で決着した。**
`docs/win32-migration/dev-notes.md`「推測を 1 往復ぶつけるより、判定材料を 1 往復で採る」を、
**利用者に対しては守れていなかった**（確認セッションには守っている）。

## Notes

- **アイコンを引くのは一覧だけではない。**タブの見出しも `ShellImageList.IndexOfPath` を使うが、
  あちらは `ByPath` で覚えているうえ、枚数が少ないので効かない
- **タブ帯のアイコンは `IndexOfPath`（`ByPath` あり）**なので、この不具合の範囲外
- 関連: なし（新しい系統）
- **閉じるのは利用者が「速くなった」と確認してから。**第 2 段まで入れたが、
  **実機で測っていない**（手元に Windows が無い）
- **第 2 段で新しく増えたもの**——スレッド 1 本（`ShellIcons`）。
  `ShellNamespace` に続いて 2 本目。**メモリ要件に響く量ではない**が、
  `Ctrl+Shift+G` のスレッド数が 1 増える（確認のときに退行と読み違えないように）
- **見え方が変わる。**一覧が出た直後は `.exe` が**汎用の絵**で並び、
  そのあと個別の絵に差し替わる。**エクスプローラーと同じ**だが、
  「一瞬ちがう絵が出る」ので不具合と読まれうる
