# installer 開発メモ

## 実装上の判断

| 判断内容 | 理由 |
|----------|------|
| **Inno Setup 6** を使う | ユーザーごとインストールが 1 行（`PrivilegesRequired=lowest`）。単一の `.exe` で配れる。無人インストールや GPO 配布の予定が無いので MSI の利点が活きない |
| **配るのは exe 1 本だけ** | `pdb`（16.3MB）は利用者に不要。`Assets\app.ico` は**実行時に誰も読んでいない**（アイコンは exe に埋まっている PE リソースから取る）。3 つ入れると 5 倍以上に膨らむ |
| **起動中の検出は窓のクラス名** | `FindWindowByClassName('ExtendExprorer.MainWindow')`。**アプリ側の変更が 0** で済む。プロセス名より確か（別の場所に置いた exe でも拾える） |
| **`CloseApplications=no`** | Restart Manager に閉じさせると、閉じる経路が `WM_ENDSESSION` になる。**そこは session E-13（ログオフ）として未確認のまま残っている道**で、入れ替えのついでに配置を失うのが最悪 |
| **アンインストール時に設定を消すか聞く。既定は「残す」** | 入れ直しのときに消えている方が痛い。`MB_DEFBUTTON2` で「いいえ」に当てておく |
| **同じ版・古い版でも止めない** | 止める作りにすると、**壊れたときの入れ直し**と**版を戻す操作**の両方ができなくなる |
| **版数は `csproj` の `<Version>` だけに書く** | CI がそれを読み、**exe に焼かれたファイルバージョンと突き合わせて**から ISCC へ渡す。人が 2 か所に書かない |
| 成果物は**足す**（`ExtendExprorer-setup`） | `ExtendExprorer-win32-x64` は確認をお願いしている側の道具と依頼書 20 回ぶんが指している。名前は変えない |

## 発生した問題と対処

| 問題 | 対処 |
|------|------|
| **壊れたダウンロードを基準にして、exe の大きさを 2 回間違えた** | 下記 |
| 手元で `.iss` の構文を試せない | CI に投げるしかない。1 回目で通った（`ISCC` 終了コード 0） |
| `pyyaml` が無くて `build.yml` の構文検査ができない | タブ・行末空白・ステップ数・成果物名を手で見た。本検査は CI |

### ★ 壊れたダウンロードを基準にしてしまった（2026-09-23）

最初 `gh run download` が **`failed to run git: fatal: not a git repository`** で失敗したのに、
**ファイルは一部できていた**（`a.zip` が残っていた）。それを基準にして

- exe = **3.35MB** ← 実際は **3.55MB**（3,720,704 バイト）
- pdb = **15.4MB** ← 実際は **16.3MB**（17,076,224 バイト）

と書き、**overview / design / test-cases / install.md の 4 つに書いた。**

気づいたのは、**インストーラーを入れたあとの exe が 3,720,192 バイト**で、
「`<Version>` を足しただけで **+206KB** も増えるのか？」が引っかかったため。
**きれいに取り直したら、増えていたのではなく最初の数字が間違っていた**
（本当は **−512 バイト**。版数の資源が詰め物と入れ替わった分）。

- **失敗したコマンドの出力を、成功したものとして使った。**
  `gh run download` は `tail -1` でエラー行を落としていて、**失敗が見えていなかった**
- **おかしいと思った差（+206KB）が、実は自分の基準値の誤りだった。**
  「変化」を疑う前に、**比較の両側が同じ取り方か**を見る
- 数字を 4 つの文書へ写したので、直すのも 4 か所になった。
  **実測値は 1 か所（design.md）に置いて、他は参照にする方がよかった**

### exe は「そのまま」ではない

`<Version>` / `<Company>` / `<Product>` を入れたので、
**`ExtendExprorer-win32-x64` の exe も 1 度ビルドし直っている。**

| | `98a34dc` | `4afa760` |
|---|---|---|
| 大きさ | 3,720,704 | **3,720,192**（−512） |
| SHA256 | `7afc84cb…` | **`7cad3c7f…`**（一致しない） |

**成果物の「名前」は変えていないが、「中身」は変わった。**
最初 design.md と `build.yml` に「名前も中身も変えない」と書いていたので直した。
**退行の確認（E-30 / E-33）は形だけの項目ではない。**

### ★ 依頼書に書いたパスも「主張」である（2026-09-28）

実機確認で、**こちらの書き方が実物と違っていた所が 2 つ**出た。どちらも動作は正常。

| 書いたもの | 実物 |
|---|---|
| `…\Start Menu\Programs\ExtendExprorer.lnk` | **`…\Programs\ExtendExprorer\ExtendExprorer.lnk`**（**フォルダ**の中） |
| 「UAC は出ません（ユーザーごとインストール）」 | **最初にインストールモードを尋ねる画面が出ていた。**「UAC が出ない」は**利用者が「現在のユーザー用」を選んだ結果** |

**1 つ目は、確認そのものを無意味にしかけた。**E-23 は「残骸が無いこと」を見る項目だが、
**書いた方のパスはインストール前も後も存在しない。**そこだけ見れば必ず「無い」になる。
確認セッションの道具も最初そうなっており、**H-20 に入る前に気づいて直した**と報告された。

> **依頼書に書いたパスやキーは、それ自体が「主張」である。**
> **「見つからない」が証拠になるのは、同じ探し方で「見つかった」ことがある場合だけ。**

前回の**「`0 行` を数える前に、その文字列が実行ファイルにあるか見る」と同じ形**で、
surface が違うだけ。**「無いこと」を確かめる項目には、必ず対照の 1 つを添える。**

### 「すべてのユーザー用」は選べないようにした（2026-09-28）

`PrivilegesRequiredOverridesAllowed=dialog` を付けていたので、
**最初に「現在のユーザー用 / すべてのユーザー用」を尋ねる画面**が出ていた。

**外した。**理由は 1 つ。

- 「すべてのユーザー用」は [overview.md](./overview.md) で**作らないと決めた枝**
- 昇格・`%ProgramFiles%` 配下・`HKLM` の登録・そこからのアンインストールは**一度も通していない**

> **誰も通していない道を選べる状態**の方が、**画面が 1 枚減ること**より悪い。

外した副作用として、**「UAC は出ない」が枝に依らず成り立つ**ようになった。

### メモリの実測値が 31.8MB ではなかった（2026-09-28）

確認セッションが `36.7MB` を測り、**同じ測り方で前の版と並べ直した**。

| ビルド | WorkingSet（3 回） |
|---|---|
| `98a34dc` | 36.6 / 36.6 / 36.5 MB |
| `4afa760` | 36.4 / 36.6 / 36.6 MB |

**2 つの版で差が無い＝退行ではない。**ここは確かめられている。

**31.8MB との差の理由は分けていない。**2026-09-11 の実測 #3 は
**特定の `session.json` を復元した条件**で取っているので、
タブ・ペインの数が効いている可能性はあるが、**それはこちらの推測**でしかない。
OS の更新・測り方・ビルドの構成も候補として残る。

**原因を書かずに、切り分ける 1 つを test-cases E-34 に置いた**——
**31.8MB を測ったときと同じ `session.json` を復元して測る。**
移行の比較で使った「同じ session を両方に復元する」やり方と同じ。

### SmartScreen は「出ること」までしか確認できていない（2026-09-28）

**警告が出ることは確認できた**（文言・`Unknown Publisher`・`smartscreen.exe` の起動・
`Get-AuthenticodeSignature` が `NotSigned`）。

**「Run」を押したあとが進まなかった。**ダイアログが不可視のまま生き続け、
`ShellExecute` が 1 分以上戻らず、セットアップも起動しなかった。
やむなく Mark of the Web を外して以降を測った、と報告されている。

**アプリ側の話ではない。**未了として残すが、**これを製品の課題として持ち越さない。**

## 設計からの変更点

| 変更内容 | 理由 |
|----------|------|
| `RestartApplications=no` を足した | `CloseApplications=no` と対。閉じさせないなら開き直しもさせない |
| `DisableProgramGroupPage=yes` を足した | スタートメニューのフォルダ名を聞く画面は、1 本しか入れないアプリでは無駄 |
| 入れ方の文書を `docs/installer/install.md` に置いた | `README.md` がリポジトリに無く、**公開リポジトリの表紙を新しく作るのは依頼の範囲を越える**ため、作るかは利用者に確認してから |
| **`PrivilegesRequiredOverridesAllowed=dialog` を外した**（2026-09-28） | 上記。**作らないと決めた枝を選べてしまう**ため |
| **スタートメニューはフォルダのまま**にした | Inno の既定の出力で、**不具合ではない**。1 つしか入らないフォルダを嫌って「群」を作らない形にもできるが、**それは別の変更**——同じ確認の回に 2 つの差を入れると、どちらが原因か分けられなくなる。**やるかは利用者に確認してから** |

## 今後の課題

- **コード署名。**未署名なので SmartScreen が出る。**自己署名では解決しない**（評判を見る仕組み）。
  有料の証明書（OV / EV）を買うかどうかから
- **GitHub Release への公開。**公開リポジトリなので、未署名の exe を誰でも落とせる状態になる。
  いまは CI 成果物のまま（2026-09-23 の判断）
- **自動更新。**メモリ要件（30MB 前後）に通信とスケジューラを足すことになる
- **`README.md`。**作るなら `install.md` を指すだけで足りる

## ユーザへの要望

  **今回はレジストリとスタートメニューに書く回**なので、依頼書に戻し方を全部書いた
- **古い版が起動したままになっている。**2026-09-23 の報告で
  `tmp/bin/win32-730be7b/ExtendExprorer.exe` が 9/22 から動いていた。
  **`session.json` を取り合う**ので、インストーラーを試す前に閉じてもらう必要がある
