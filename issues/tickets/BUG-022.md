# BUG-022: ウィンドウを狭めると一覧が押し出されて消える（240px 確保がリサイズに効かない）

- **State**: Fixed
- **Reported**: 2026-08-24
- **Area**: win32-migration / folder-tree / `src/ExtendExprorer.Win32/UI/MainWindow.cs`

## Summary

フォルダツリーを広げた状態でウィンドウ幅を縮めると、ツリーが幅を保ったまま
一覧が押し出され、窓幅 620px で一覧もタブ帯も**完全に見えなくなる**。
仕切りのドラッグ側では「一覧に 240px を残す」制限が効いている。

## Reproduction

1. ツリーを 600px まで広げる
2. ウィンドウ幅だけを縮めていく

| ウィンドウ幅 | ツリー幅 | 一覧幅 |
|---|---|---|
| 1200 | 600 | 579 |
| 800 | 600 | 179 |
| 620 | 600 | **0**（一覧・タブ帯とも消える） |

ウィンドウを広げれば元に戻る。

## Expected

`docs/explorer/folder-tree/spec.md` の「右の一覧には常に 240px 以上を残す」は、
仕切りのドラッグだけでなく**ウィンドウのリサイズにも**適用されること。

## Cause

制限を**ドラッグの処理の中だけ**に書いていた（`OnTreeSplitterDragged`）。
配置を決める `Layout()` は、記憶している幅をそのまま使っていたため、
ウィンドウが狭くなっても縮まなかった。**制限は「値を決める場所」ではなく
「配置を決める場所」に置くべきだった。**

## Fix

`Layout()` 側で、記憶している幅と「一覧に 240px を残せる幅」の小さい方を使うようにした。

**記憶している幅（`TreeWidth`）は書き換えない。**窓を狭めたのは一時的なことなので、
広げ直せば元の幅に戻る（第 5 段の session 保存でも、狭めた瞬間の値が焼き付かない）。

窓が極端に狭く、240px を残すとツリーが下限（120px）を割る場合は、
ツリー側を 0 まで詰める。一覧が見えなくなるより、ツリーが見えなくなる方が実害が小さい。

## Notes

同じ「制限を配置の側に置く」原則は、第 3b 段で入れるアドレスバーの帯にも当てはまる。
