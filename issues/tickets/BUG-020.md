# BUG-020: 読めないフォルダが「アクセスが拒否されました」ではなく「空です」になる

- **State**: Fixed
- **Reported**: 2026-08-15
- **Area**: win32-migration / file-list（`src/ExtendExprorer.Win32/Services/FileSystemService.cs`）

## Summary

列挙が拒否されるフォルダを開くと、一覧の中央に「アクセスが拒否されました」ではなく
**「このフォルダーは空です」**が表示される。読めないことと空であることが区別できない。

## Reproduction

1. `C:\Windows\System32\config` を開く（起動時の指定でもダブルクリックでも同じ）
2. 観測: 中央に「このフォルダーは空です」

## Expected

「アクセスが拒否されました」（file-list 仕様のエラーケース）。

## Cause

`DirectoryInfo.EnumerateFileSystemInfos()` を**引数なし**で呼んでいた。
この場合の列挙条件は .NET の既定に委ねられ、読めない対象が**例外ではなく
「その項目を飛ばす」**扱いになる。結果として列挙は成功し、項目 0 件の
`ListOk` が返るため、アプリ側からは空のフォルダと区別が付かなかった。

`catch (UnauthorizedAccessException)` は書いてあったが、そもそも例外が飛んでいなかった。

## Fix

列挙条件を明示した（`EnumerationOptions`）。

- `IgnoreInaccessible = false` … 読めなければ例外にする
- `AttributesToSkip = 0` … 隠し・システムの項目を除外しない（この一覧では常に表示する仕様）
- `RecurseSubdirectories = false` … 子フォルダへは降りない

子フォルダへ降りないので、`IgnoreInaccessible = false` で例外になるのは
「開こうとしたフォルダ自身が読めない」場合だけ。

- **Fix commit**: 4d78c2f

## Notes

現行 WinUI 3 版の `FileSystemService` にも同じ書き方が残っている（同じ症状のはず）。
移行で置き換わる箇所なので新実装のみ直した。旧版で困る場面が出たら別途対応する。
