# BUG-025: リネームで既にある名前に変えると、置換の確認ではなくエラー 0x80070057 になる

- **State**: Fixed（実機での確認待ち）
- **Reported**: 2026-08-29（1 度だけ）／2026-08-30（毎回再現）
- **Area**: win32-migration / `src/ExtendExprorer.Win32/Services/ShellFileOperations.cs`

## Summary

インライン リネームで**既にあるファイル名**に変えて確定すると、
エクスプローラーと同じ「ファイルの置換またはスキップ」ではなく、
シェルのエラーダイアログ `0x80070057`（パラメーターが間違っています）が出て中断する。

データは無傷でアプリも落ちないが、**上書きリネームができない**。

## Reproduction

1. 同じフォルダに `abc.txt` と `bbb.txt` を置く
2. `abc.txt` を F2（または 2 回目クリック）で編集し、`bbb.txt` に変えて Enter

```
1 件の中断されたアクション
予期しないエラーのため、ファイル名を変更できません。
エラー 0x80070057: パラメーターが間違っています。
[再試行] [スキップ] [キャンセル]
```

**壊れているのはファイルのリネーム衝突だけ**（2026-08-30 実測）。

| 操作 | 結果 |
|---|---|
| ファイル名 → 既存のファイル名 | ❌ `0x80070057` |
| フォルダ名 → 既存のフォルダ名 | ✅ 「フォルダーの上書きの確認」 |
| コピー貼り付けの衝突 | ✅ 「ファイルの置換またはスキップ」 |
| 衝突しないリネーム／大文字小文字だけの変更 | ✅ 通る |

## Expected

エクスプローラーと同じ「ファイルの置換またはスキップ」が出ること。

## Cause

**特定できていない。**

- 8/29 のセッションでは 5 回すべて成功し、8/30 は 11 回以上すべて失敗した。
  同じビルド（`8962d16`）で結果が変わっているため、**コードの変更が原因ではない**
- 確認側が「起動直後か／メニューを開いたか／間隔／名前／並び順／Tab の有無」を
  つぶしたが、いずれも関係なかった

判明しているのは**経路の差**だけ。`IFileOperation::RenameItem` は失敗し、
同じ瞬間に `CopyItem` / `MoveItem`（貼り付け）は正しい衝突ダイアログを出す。

## Fix

**改名を `RenameItem` から「同じフォルダへの `MoveItem`」に変えた。**
`MoveItem(item, 親フォルダ, 新しい名前, null)` は名前を変えながらの移動＝改名で、
**貼り付けの衝突で正しいダイアログが出ている経路そのもの**。

あわせて `MoveItem` / `PerformOperations` の HRESULT を `--diag` に残すようにした。
これまで戻り値を捨てていたため、失敗しても手元に数字が無かった。

- **Fix commit**: `aaac5c2`

## Notes

**「直った」とは主張していない。**原因が特定できておらず、環境側の状態で
出たり出なかったりしている。正しい経路へ寄せたうえで、次に失敗したときに
数字が残るようにした、という段階。
