# BUG-047: ファイルを開くとき `ShellExecuteExW` を UI スレッドで呼んでいる

- **State**: Open
- **Reported**: 2026-10-04（[BUG-046](./BUG-046.md) の調査中に見つけた。**利用者からの報告ではない**）
- **Area**: file-list（`UI/FileListView.cs` / `Services/ShellContextMenuService.cs`）

## Summary

一覧でファイルをダブルクリック（または Enter）したとき、
**`ShellExecuteExW` を UI スレッドで同期的に呼んでいる。**

```
UI/FileListView.cs:1289          Activate（ダブルクリック / Enter）
  → Services/ShellContextMenuService.cs:51   ShellExecuteExW（SEE_MASK_INVOKEIDLIST）
```

**同じ呼び出しが 1 分以上返ってこないことを、2026-09-28 の確認で既に測っている**
（H-02。インストーラーに Mark of the Web を付けて実行したとき）。
**2026-10-04 には「戻らなかった」という報告も出ている**（BUG-046）。

**その仕組みを、こちらは UI スレッドで呼んでいる。**

## ★ 一度「持ち越さない」と判断したのが誤りだった

H-02 の報告を受けて、こう書いた。

> **`ShellExecute` が戻らないのはアプリ側の話ではないので、製品の課題として持ち越しません。**

**あの観測は「`ShellExecute` は長く返ってこないことがある」という仕組みの話**で、
**その仕組みを使っているかどうかは別に見るべきだった。**
**使っていた。しかも UI スレッドで。**

## Reproduction（未確認）

Mark of the Web が付いた未署名の `.exe`（ブラウザで落としたインストーラーなど）を、
**この一覧からダブルクリックする。**
**SmartScreen の問い合わせが終わるまで窓が固まる**はず。

ほかに効きうる場面: UAC の昇格を伴う exe、届かないネットワークパスのファイル、
重いシェル拡張が `open` の verb に入っている場合。

## Expected

**窓が固まらない。**開くのに時間がかかっても、他のタブや一覧が触れる。

## Cause

**BUG-043 / BUG-044 と同じ家族の 4 つ目。**

| | 面 | 状態 |
|---|---|---|
| BUG-038 / BUG-041 | アイコンを引く（一覧・タブ帯） | Fixed |
| BUG-043 | session の復元（起動時） | Fixed |
| BUG-044 | ツリーのノードのクリック | Fixed |
| **BUG-047** | **ファイルを開く（ダブルクリック / Enter）** | **ここ** |

**`grep Directory.Exists` では見つからない。**あちらは**パスの確認**で、
こちらは**シェルの実行**。

> **数え直す括りは「`Directory.Exists`」ではなく、
> 「UI スレッドから呼ぶと待ちうるシェルの関数」だった。**

**手前の `SHParseDisplayName` も同じ**（同じ関数の中・シェルを触る）。

## Fix（未着手。**調べてから決める**）

**裏のスレッドへ出すのは自明ではない。**

- `SEE_MASK_INVOKEIDLIST` は**コンテキストメニューのハンドラを呼ぶ**ので、
  **相手が STA の COM オブジェクト**でありうる。MTA の裏スレッドから呼ぶと挙動が変わりうる
- シェルの一部の verb は**メッセージポンプのあるスレッド**を要求する
- `ShellNamespace` / `ShellIcons` の MTA スレッドをそのまま使い回せるかは**調べていない**
- `hwnd` を渡しているので、**ダイアログの親が別スレッドの窓になる**。
  許されてはいるが、活性化とフォーカスの扱いが変わりうる

**推測で入れない。**先に調べることを書き出す。

1. `ShellExecuteEx` を**ポンプを持つ専用の STA スレッド**から呼ぶのが定石かどうか
2. ポンプを書くなら、**それ自体が確認の対象になる**（`ShellNamespace` の doc に
   「ポンプの無い STA はデッドロックの温床で、ポンプを書くとそれ自体が検証の対象になる」とある）
3. **そもそも固まる場面を実機で踏めるか**（Mark of the Web 付きの exe で踏めるはず）

## Notes

- **今回の利用者の事故（BUG-046）はこれではない。**あちらは Windows の
  エクスプローラーが固まったもので、こちらのコードは走っていない
- **「同じ家族」を数え直す作業そのものが、まだ済んでいない。**
  `ShellFileOperations`（`IFileOperation.PerformOperations`）・
  `ListDragSource`（`DoDragDrop`）も UI スレッドだが、
  **あちらはシェルが自分で進捗を出してポンプを回す**ので事情が違う。
  **一覧にして評価する**のが次の作業
