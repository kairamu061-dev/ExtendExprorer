# BUG-007: フォルダ移動を挟むとインラインリネームが開始しなくなる

- **State**: Closed
- **Reported**: 2026-07-26
- **Area**: file-list / rename（`src/ExtendExprorer/Views/FileListView.xaml.cs`）

## Summary

あるタブで一度インラインリネームを開始したあとフォルダ移動を挟むと、そのタブでは以後インラインリネームが
まったく開始しなくなる。選択・ダブルクリック起動・右クリックは正常。新しいタブ／ペインを開くと復活する。

## Reproduction

1. フォルダを表示し、間を空けた2回目クリックでリネーム編集に入る（成功）
2. 同じタブでアドレスバー等から別フォルダへ移動し、元のフォルダへ戻る
3. 同じ操作を行う → リネーム編集に入らない（Up・戻る・進む・再入でも回復しない）
4. 新しいタブで同じフォルダを開くと入る

## Expected

移動を挟んでも、同じタブでインラインリネームが従来どおり開始する。

## Cause

`FileListView` のリネーム状態フィールド `_renamingEntry` が移動時に解除されずに残っていた。

- `OnItemTapped` の冒頭に `if (_renamingEntry is not null) return;` があり、残留すると以後すべてのタップが早期 return する。
- 解除は `CommitRename` でのみ行われるが、`CommitRename` は `box.DataContext is EntryViewModel entry && entry.IsRenaming` が
  成立しない場合に何もせず return していた。移動で `TabViewModel.LoadAsync` が `Entries` を作り直すと、
  編集中の `TextBox` は ListView のコンテナ再利用によって別の `EntryViewModel` を DataContext に持つか
  破棄されるため、その後に届く `LostFocus` ではこの条件が成立せず `_renamingEntry` が残る。
- 同一タブ内の移動では `FileListView.ViewModel` セッターが呼ばれないため、そこで行っている
  リセット（`CancelPendingRename()` / `_renamingEntry = null`）も走らない。

## Fix

1. `TabViewModel.Navigated` を `FileListView` で購読し、移動・再読込のたびに
   `ResetRenameState()`（`_renameTimer` 停止・`_pendingRename` / `_renameCandidate` / `_renamingEntry` クリア）を実行する。
2. `CommitRename` を「どの経路で呼ばれても最後に必ず `_renamingEntry` を落とす」形に整理し、
   DataContext が入れ替わっていた場合でも状態が残らないようにした。

- **Fix commit**: `5f97ded`
