# BUG-031: タブ帯が折り返すと、掴んだタブの見分けがずれる

- **State**: Fixed（実機確認待ち）
- **Reported**: 2026-09-06
- **Area**: win32-migration / tabs / `src/ExtendExprorer.Win32/UI/TabStripView.cs`

## Summary

タブ帯が **2 行以上に折り返している**とき、掴んだタブの番号が**枚数を超える**。
そのため、

1. **別のペインへ移せない**（何度やっても `[tab] 最後の 1 枚は移せない`）
2. 並べ替えのログの番号が持っている枚数を超える（26 枚なのに `31` `36`）

## Reproduction

1. 左ペインのタブを 26 枚まで増やす（帯が 3 行に折り返す）
2. 右ペインを作り、タブを 3 枚にする
3. 左のタブを右ペインの帯へドラッグして落とす

| 操作 | ログ |
|---|---|
| 1〜3 行目のどのタブ → 右ペインへ | `[tab] 最後の 1 枚は移せない` |
| （対照）2 行目のタブを帯の中で並べ替え | `[tab] 並べ替え **31** → 3` |
| （対照）3 行目のタブを帯の中で並べ替え | `[tab] 並べ替え **36** → 3` |

**帯を 1 行に戻すと、同じ操作が通る**（`[tab] 別のペインへ 0 → 挿入 1`）。
`Ctrl+Shift+G` の `TabModel=29/29` で、実際の枚数は 29 枚と裏が取れている。

## Expected

行数によらず、掴んだタブが正しく見分けられること。

## Cause

**矩形の表が枚数の 2 倍になっていた。**`LayoutTabs` の書き順の問題。

```csharp
_rects.Clear();
…
SetRows(row + 1);          // ← ここで HeightChanged が飛ぶ
for (…) { _rects.Add(…); } // ← 戻ってきてから、さらに積む
```

`SetRows` は行数が変わったときだけ `HeightChanged` を発火する。
これを受けた親は並べ直し、その中で `SetBounds` → **`LayoutTabs` へ再入する**。
再入した側は `_rects` を作りきって戻り、**外側の `for` がその上にもう一組積む**。

- 当たり判定（`HitTest`）は**後ろから**走査するので、積み増した側（＝枚数以上の番号）に当たる
- その番号は `_pane.Tabs` の範囲外なので、`DetachTab` が null を返す
  → **「最後の 1 枚は移せない」に化ける**（メッセージが実態と違っていた）
- **行数が変わるときだけ**発火するので、1 行に収まっていれば起きない

観測がすべて説明できる。

## Fix

**矩形は手元で組みきってから入れ替え、行数を知らせるのは最後**にする。
これで再入しても、外側が積み増すことは無い。

あわせて、**同じ壊れ方が次に起きたら分かるように**ログへ枚数を添える。

- `[tab] 並べ替え N → M（K 枚）`
- 範囲外なら `[tab] 番号が範囲外 N／K 枚`（「最後の 1 枚」と区別する）

- **Commit**: `847c03b`

## 学び

- **通知を出す位置は、状態を作りきったあと。**イベントを 1 つ発火するだけで
  同じ関数へ再入しうる（親のレイアウトを経由して戻ってくる）
- **「起きてはいけない値」は、起きたときにそう分かるログにする。**
  今回は範囲外の番号が「最後の 1 枚は移せない」という**別の正常な結果**に化けていて、
  症状から原因が遠かった
- 確認をお願いしている側が**番号と実際の枚数を並べて**くださったので、
  ログを見た瞬間に「表が壊れている」と分かった。数字を 2 つ並べる価値
