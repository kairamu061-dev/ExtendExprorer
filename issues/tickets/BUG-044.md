# BUG-044: ツリーで届かないネットワークの場所をクリックすると、その場で約 21 秒固まる

- **State**: Fixed
- **Reported**: 2026-10-04（動作確認フィードバックで指摘。**`grep` で見つけてもらった**）
- **Area**: folder-tree（`UI/FolderTreeView.cs`）

## Summary

**[BUG-043](./BUG-043.md) と同じ形**が、**ツリーのノードをクリックする経路**に残っていた。

```csharp
// FolderTreeView.Invoke — WM_NOTIFY の中＝UI スレッド
if (node.Path is { Length: > 0 } path && Directory.Exists(path))
```

BUG-043 では**起動経路**から外したが、**こちらは見ていなかった。**

## Reproduction（**未確認**）

ツリーに「届かないネットワークの場所」のノードがある状態で、そのノードをクリックする。
**起動時ではなく、クリックした瞬間に約 21 秒固まる**はず。

> **確認セッションの PC では踏めなかった。**ツリーの根が
> `ホーム / ギャラリー / OneDrive / Dropbox / ダウンロード / デスクトップ / ドキュメント /
> ピクチャ / ビデオ / ミュージック / PC / ボリューム (E:) / ネットワーク / Linux` で、
> **パスを持つものはすべてローカル**だったため。
> 割り当てドライブ（`Z:` など）を作れば踏めるが、**システムの状態を変えるのでやっていない**。

## Expected

**クリックしてすぐ反応する。**開けなければ一覧側で「パスが見つかりません」が出る。

## Cause

`Directory.Exists` が**「移動するか、その場で展開するか」の判断**に使われていた。

> `SFGAO_FILESYSTEM` が立っていてもパスが開けないもの（コントロールパネルの一部など）が
> あるので、`Directory.Exists` と**両方**見る。移動できないノードは**その場で展開する**
> ——`PC` をクリックしたらドライブが出る、という動きになる。

**この判断自体は要る。**消すと `PC` のクリックが壊れる。

## Fix

**消さずに、待たない形にした。**

```csharp
if (node.Path is { Length: > 0 } path && (!CanProbeQuickly(path) || Directory.Exists(path)))
```

`CanProbeQuickly` は **UNC と、固定ディスクでないドライブを false** にする。

- **確かめないパスは、そのまま一覧へ渡す。**開けなければ一覧側の**非同期の**読み込みが
  失敗して板が出る。**固まるより、待っていると分かる方がよい**
- **確かめるのは固定ディスクのパスだけ**なので、コントロールパネル系の判断は**今までどおり**
- `GetDriveType`（`DriveInfo.DriveType`）は**ローカルの割り当て表を読むだけ**で
  相手に接続しないので、ここで呼んでも待たない
- 判定できないもの（例外）は**「確かめない」側へ倒す**——**待つ方に倒さない**
