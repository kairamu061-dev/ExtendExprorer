# BUG-015: 起動直後の初回フォルダ表示で、一覧のアイコンが色なしになる

- **State**: Fixed
- **Reported**: 2026-08-09
- **Area**: shell-icons（`ShellIconCache`）

## Summary

アプリ起動直後、**最初に表示するフォルダ**の一覧アイコンが色付きのシェルアイコンにならず、
フォールバックのグリフ（輪郭だけのフォルダ）で表示される。**左のツリーは色付きのまま**。
別フォルダへ移動するか再読込すると即座に直り、以後は正常。

## Reproduction

1. アプリを起動する（session 復元・任意のフォルダ）
2. 最初に表示された一覧のフォルダアイコンを見る

- 発生率 **約 85%**（8 回中 6 回、追加試験を含め約 13/15）
- ホーム・`D:\...`・`C:\Windows` いずれでも発生 → **フォルダに依存せず、起動という状況に依存**
- 待っても直らない（t≈1s / 4s / 9s で変化なし）
- **移動・再読込で即回復**（0/12 → 11/12）。再起動は不要

## Expected

起動直後の初回表示から、一覧のフォルダ・ファイルアイコンが色付きのシェルアイコンで表示される。

## Cause

起動直後は数百 ms のあいだ `SHGetFileInfoW` が空を返しつづける。ここまでは BUG-010 と同じだが、
**その一度の失敗が、その画面のフォルダ行すべてに広がる**点が本件の本体。

- 一覧のフォルダ行は汎用フォルダアイコンをキー `<dir>` で**共有**しており、同時要求は
  `InFlight` の Task を共有する。→ 最初の 1 回が失敗すると、その読み込みの**全行**が同時にグリフに落ちる
  （観測値 0/12 は「12 回失敗した」のではなく「1 回の失敗を 12 行が共有した」）
- 各 `EntryViewModel` はアイコンを一度しか要求しないため、**表示したままでは再試行が起きない**
  （＝待っても直らない。移動で VM が作り直されて初めて再試行される）
- BUG-010 で入れたリトライは**即時 1 回**だけで、数百 ms 続く起動直後の状態には届かない
- **ツリーが無事だった理由**: ツリーのノードは `distinctByPath` でパス単位のキーを使うため
  キーを共有せず、かつ要求のタイミングが一覧より後ろにずれる

## Fix

1. `LoadAsync` のリトライを**即時 1 回**から**待ち時間を延ばしながら 4 回**（0 / 120 / 350 / 800ms）に変更。
   共有 Task の中で再試行するので、成功した時点で**その Task を待っている全行に一斉に反映**される
2. `ShellIconCache.WarmUp()` を追加し、`MainWindow` の生成時＝**最初のフォルダを読み込むより前**に
   汎用フォルダ／拡張子なしファイルのアイコン取得を始めておく

- **Fix commit**: 本チケットと同じコミット

## Notes

- BUG-010（失敗を恒久キャッシュしない）の修正は有効で、**回復するようになっていた**（E-53 相当を検証で確認）。
  本件は「回復はするが、引き金が残っていた」ぶんで、BUG-010 の再オープンではなく新規とした。
- 検証側がこれまで見逃していたのは、E-52 を**別フォルダへ移動してから**測っていたため。
  以後アイコンは「**コールドスタート直後の初回表示**」でも確認する（test-cases に E-56b として追加）。
