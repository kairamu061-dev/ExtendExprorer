# BUG-026: コンテキストメニューの「コピー」「切り取り」が効かない

- **State**: Fixed（実機での確認待ち）
- **Reported**: 2026-08-30
- **Area**: win32-migration / context-menu / `src/ExtendExprorer.Win32/Program.cs`

## Summary

シェルのコンテキストメニューから「コピー(&C)」「切り取り(&T)」を選んでも、
**クリップボードに何も置かれない**。同じメニューの他の項目（削除・パスのコピー・
プロパティ・送る）は正しく動く。キーボードの Ctrl+C は効く。

## Reproduction

1. ファイルを右クリック →「コピー」
2. クリップボードを見る → 変化なし（実行前に置いた文字列がそのまま残る）

| メニュー項目 | 結果 |
|---|---|
| コピー / 切り取り | ❌ 変化なし |
| パスのコピー / 削除 / プロパティ / 送る | ✅ |

## Expected

エクスプローラーと同じくクリップボードに置かれ、貼り付けられること。

## Cause

**`OleInitialize` を呼んでいなかった。**

シェルの「コピー」「切り取り」は `OleSetClipboard` でデータを載せる。
これは**呼び出しスレッドが OLE 初期化済みであること**が前提で、
`[STAThread]` による `CoInitialize` だけでは足りない。
初期化されていないと `OleSetClipboard` は失敗するが、**例外も出ず、戻り値も見えない**ので
「メニューは動いているのに何も起きない」という形になる。

アプリ自前の Ctrl+C は `OpenClipboard` / `SetClipboardData`（OLE を経由しない）で
書いているため影響を受けなかった。これが「Ctrl+C は効くのにメニューは効かない」の理由。

確認側の見立て（「まだ `OleInitialize` していないのでは」）がそのまま当たっていた。

## Fix

起動時に `OleInitialize` を呼び、終了時に `OleUninitialize` する。
`--diag` に戻り値を残す（`[start] OleInitialize=0x........`）。

第 4c 段のドラッグ＆ドロップでも必要になるので、そちらでの追加分は無い。

- **Fix commit**: `aaac5c2`

## Notes

OLE の初期化は起動経路を変えるため、**起動そのものの退行**（[BUG-013](./BUG-013.md) の系統）に
注意が要る。
