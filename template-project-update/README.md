## ★ コピーしたあとに 1 つやること

**`/translate-to-jp` を実行する。**

`agent-rules.md` / `project-structure.md` / 新しい `SKILL.md` に対応する
`_jp/` の日本語版が必要で、それはこの skill が作る。
（`_jp/` を手で書いていないのは、`agent-rules.md` が
「`_jp/` 配下のファイルは読まない・参照しない」と定めているため。）

```
_jp/agent-rules.md
_jp/project-structure.md
_jp/skills/verify-request/SKILL.md
```

## 前提

- `.gitignore` は `tmp/` を既に無視しているので変更不要
- `/verify-request` は `gh`（GitHub CLI）と `git` を使う。
  無い環境では数字を `★要取得` と書き出して止まるので、**もっともらしい値が混ざることはない**
- 成果物の名前は決め打ちしていない（`gh api` で run の成果物を列挙する）

## 入れた理由（どれも実際に代償を払ったもの）

| | 何が起きたか |
|---|---|
| **A** 確認依頼の skill | 71 回やった作業に足場が無く、**数字を 2 回・パスを 1 回**写し間違えた。パスの誤りは**確認そのものを空にしかけた**（前も後も「無い」と出るパスを書いた） |
| **B** 4 つの規則 | 71 回やったのに**規則がどこにも無かった。**「確認できなかった」を「問題ではない」と丸めて、**6 日後に利用者が同じ段で止まった** |
| **C** 網の起点を spec へ | 移植の網を**テストケースから**作ったので、テストケースの無い仕様項目が最初から載らず、**16 日間気づかなかった** |
| **D** 測った／推測の分離 | 唯一の反復失敗がこれ。**別プロセスで起きたことを自分の症状として票に書いた**ことがある |
| **E** テストの線引き | **12,878 行に対してテスト 365 行**。入れたのは最後の 1 週間で、「全部 UI だから無理」で 6 週間止まっていた |

## 正直に

**A は実際に動かして確かめた**（成果物の計測・汚れた作業ツリーの警告・桁区切り）。
**B〜E は、過去の失敗に対して後から書いた規則で、まだ試していない。**
次のプロジェクトで効くかどうかは、そこで測ることになる。
