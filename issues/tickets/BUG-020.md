# BUG-020: 読めないフォルダが「アクセスが拒否されました」ではなく「空です」になる

- **State**: Fixed
- **Reported**: 2026-08-15
- **Area**: win32-migration / file-list（`src/ExtendExprorer.Win32/Services/FileSystemService.cs`）

## Summary

列挙が拒否されるフォルダを開くと、一覧の中央に「アクセスが拒否されました」ではなく
**「このフォルダーは空です」**が表示される。読めないことと空であることが区別できない。

## Reproduction

1. `C:\Windows\System32\config` を開く（起動時の指定でもダブルクリックでも同じ）
2. 観測: 中央に「このフォルダーは空です」

## Expected

「アクセスが拒否されました」（file-list 仕様のエラーケース）。

## Cause

`DirectoryInfo.EnumerateFileSystemInfos()` は、**開こうとしたフォルダ自身が読めないとき、
例外ではなく 0 件を返す**。そのため列挙は成功扱いになり、項目 0 件の `ListOk` が返って、
アプリ側からは空のフォルダと区別が付かなかった。
`catch (UnauthorizedAccessException)` は書いてあったが、そもそも例外が飛んでいない。

### 1 回目の修正が外していた点

列挙条件を明示（`IgnoreInaccessible = false`）すれば例外になると考えたが、
**この設定が効くのは列挙中に出会う下位の項目だけ**で、対象フォルダ自身の
オープン失敗には作用しない。そのため症状が変わらなかった。

確認側の実測で決着した（2026-08-16）: `FindFirstFileW("<folder>\\*")` が
`INVALID_HANDLE_VALUE` ＋ `GetLastError() = 5 (ERROR_ACCESS_DENIED)` を返す。

## Fix

**列挙が 0 件だったときだけ**、`FindFirstFileW` で本当に読めるのかを直接確かめ、
`ERROR_ACCESS_DENIED` なら `ListError(AccessDenied)` を返すようにした
（`NativeMethods.IsEnumerationDenied`）。0 件のときしか呼ばないので、
通常のフォルダ表示にコストは乗らない。

`EnumerationOptions` の明示（1 回目の修正）はそのまま残す。
`AttributesToSkip = 0`（隠し・システムを除外しない）は仕様上必要なため。

- **Fix commit**: c2bf4a1（1 回目・不十分）→ 05c2e00（2 回目）

## Notes

現行 WinUI 3 版の `FileSystemService` にも同じ書き方が残っている（同じ症状のはず）。
移行で置き換わる箇所なので新実装のみ直した。旧版で困る場面が出たら別途対応する。

**教訓**: 「例外が飛ぶはず」を前提に分岐を書いたが、実際には飛んでいなかった。
確認側が `FindFirstFileW` の戻り値まで測ってくれたことで確定した。
