# BUG-020: 読めないフォルダが「アクセスが拒否されました」ではなく「空です」になる

- **State**: Fixed
- **Reported**: 2026-08-15
- **Area**: win32-migration / file-list（`src/ExtendExprorer.Win32/Services/FileSystemService.cs`）

## Summary

列挙が拒否されるフォルダを開くと、一覧の中央に「アクセスが拒否されました」ではなく
**「このフォルダーは空です」**が表示される。読めないことと空であることが区別できない。

## Reproduction

1. `C:\Windows\System32\config` を開く（起動時の指定でもダブルクリックでも同じ）
2. 観測: 中央に「このフォルダーは空です」

## Expected

「アクセスが拒否されました」（file-list 仕様のエラーケース）。

## Cause

**列挙側は壊れていなかった。**診断ログ（2026-08-16）で確定した。

```
[list] C:\Windows\System32\config
[customdraw] 呼び出し=2 ...
```

`[list]` の次に項目の行も「列挙 0 件」の行も出ていない。つまり `foreach` が
**例外を投げており**、`catch (UnauthorizedAccessException)` が最初から効いて
`ListError(AccessDenied)` を返していた。

壊れていたのは**表示**。エラー文は一覧コントロールの「項目が無いときの文字」
（`LVN_GETEMPTYMARKUP`）で出していたが、これは**空になった最初の一度しか聞かれない**。
起動直後、読み込みが終わる前に一覧は既に空で、その時点の文字（「このフォルダーは空です」）が
そのまま残り、後から届いたエラーに差し替わらなかった。

空フォルダで正しく見えていたのは、たまたま最初に決まった文字が正解だったから。

### 外した見立て 2 つ

1. `EnumerationOptions.IgnoreInaccessible = false` にすれば例外になる
   → **そもそも例外は飛んでいた**。設定は無関係だった
2. `FindFirstFileW` / `CreateFileW` で拒否を検出する
   → 列挙が 0 件になることが無いので、この経路は**一度も実行されていなかった**
   （ログに handle/gle の行が 1 行も出ていないことで判明）

## Fix

エラー文を**自前の重ね板**（`STATIC` の子ウィンドウ）で出すようにした。
エラーがあるときは一覧を隠して重ね板を出し、無いときは元に戻す。
いつ差し替えても確実に出る。

`LVN_GETEMPTYMARKUP` は「このフォルダーは空です」の表示にそのまま使う
（空の判定は最初から変わらないので、一度しか聞かれなくても問題にならない）。

0 件時の Win32 での再確認（`IsEnumerationDenied`）は**残す**。
今回は使われていないが、将来 .NET 側の挙動が変わって「例外を投げず 0 件」に
なった場合の保険になる。

- **Fix commit**: c2bf4a1（1 回目・的外れ）→ 4b1bbc5（2 回目・的外れ）→ ff46e8a（3 回目・真因）

## Notes

現行 WinUI 3 版の `FileSystemService` にも同じ書き方が残っている（同じ症状のはず）。
移行で置き換わる箇所なので新実装のみ直した。旧版で困る場面が出たら別途対応する。

**教訓**: 「例外が飛ぶはず」を前提に分岐を書いたが、実際には飛んでいなかった。
確認側が `FindFirstFileW` の戻り値まで測ってくれたことで確定した。
