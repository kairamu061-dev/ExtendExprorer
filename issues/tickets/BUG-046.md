# BUG-046: インストーラーをダブルクリックした直後に固まった（別の PC）

- **State**: Open（**原因は Windows 側**と判明。こちらにできるのは回避と署名の判断）
- **Reported**: 2026-10-04（利用者）
- **Area**: installer（原因は Windows の SmartScreen。こちらのコードは走っていない）

## Summary

> インストーラーを他の PC で使おうとしたらダブルクリックした直後にエクスプローラーが固まった
>
> （訂正）ダブルクリックした直後じゃなかった。
> **未署名の警告は出て、その後の実行を選択した後に固まった**

**「エクスプローラー」が、Windows のエクスプローラーなのか ExtendExprorer なのかで、
原因と直し方が別になる。**そこを先に分ける。

## ★ 2026-10-04: 切り分け済み — **Windows のエクスプローラー**だった

利用者に確認した。

| | |
|---|---|
| 固まったのは | **Windows のエクスプローラー**（ExtendExprorer ではない） |
| 戻ったか | **戻らず、落とすか再起動した** |

**こちらのコードは 1 行も走っていない。**未署名 ＋ Mark of the Web で
**SmartScreen が評判を問い合わせ、その応答を待って固まった**形。

### ★ 止まる場所は「ダブルクリックの直後」ではない

```
setup をダブルクリック
  ↓
「このファイルを実行しますか？ 発行元: 不明」  ← **出る**
  ↓
「実行」を押す
  ↓
★ ここで止まる。セットアップのプロセスは起動しない
```

**警告が出ることと、先へ進めることは別。**
**「警告は出たから大丈夫」ではなかった。**

### ★★ これは 9/28 に「未了」として報告された形そのもの

**2026-09-28 の H-02 の報告と、手順まで一致する。**

> 警告ダイアログは**不可視のまま生き続け**、`ShellExecute` が 1 分以上戻らず、
> セットアップのプロセスも起動しませんでした。

**2 台の別の PC で、同じ手順、同じ結果。**しかも今回は**人の手による操作**で、
**タイムアウトでも戻っていない。**
**「待てば戻る」ではない**ので、SmartScreen の問い合わせ先に届かない環境
（回線が無い・塞がれている）では**無期限に固まりうる**。

### ★ こちらの落ち度: 「確認できなかった」を「問題ではない」と扱った

9/28 の報告は、こう書かれていた。

> **これはアプリ側の話ではない**と考えますが、
> **「詳細情報 → 実行で進む」ところまでは確認できていません**。正直に未了として書きます。

**確認セッションは「未了」と書き、断定を避けていた。**
それを受けてこちらは、こう書いた。

> **H-02 は未了のまま残します。**`ShellExecute` が戻らないのはアプリ側の話ではないので、
> **製品の課題として持ち越しません。**

**「確認できなかった」と「問題ではない」は別。**
**通せなかった段は、閉じた問いではなく開いた危険**だった。
**そして実際に、インストーラーを他の PC で初めて使った人が、その段で止まった。**

> **確認が通らなかった段は、票に残す。**
> 「原因が自分の側にあるか」とは別の問題で、
> **利用者はその段を通れないと使えない。**

> **「警告が出る」と「固まる」は別の話だった。**
> 未署名を受け入れる判断（2026-09-23）は、**前者を見て決めたもの。**
> **後者は想定していなかった。**

## ★ 2026-10-04（追記）: このPC では正常に動いた

> 今このPCでリリースのsetupを落としてきて実行したら正常に動いた

**同じ setup が、この PC では通る。**＝**成果物そのものの問題ではない。**
**PC の側の違い**で決まっている。

### ★ 分かった事実: **両方の PC が、同じ 1 つのファイルを落としている**

**GitHub Release `v0.1.0`（prerelease）が公開されていた**（2026-10-04 12:09）。

```
資産  ExtendExprorer-setup-0.1.0.exe   3,488,192 バイト
      ac3844010c91b2fc18bf52953feb8f4610ac8f630001eca9eb28d79f680fdd65
      ダウンロード数 = 2
ビルド run 37201158864 / e97fd07 と完全一致
      （e97fd07 は文書のみのコミットなので、コードは 918c3ea ＝ BUG-044 の修正入り）
```

**ダウンロード数 2 ＝ 他の PC とこの PC。**
**同じハッシュのファイルが、一方で固まり、一方で通った。**

**これでファイル側の説明は全部消える。**残るのは**順番と環境**だけ。

### 違いの候補（確からしい順・改訂）

| | 候補 | 根拠・考え |
|---|---|---|
| **1** | **★ 順番。他の PC が「世界で最初にこのファイルを実行した機械」だった** | ハッシュは**新品**なので、どちらの PC にも手元の判定は無い。**最初に聞いた方が待たされ、2 番目は答えが用意されている**。事故の順序（他の PC → この PC）と一致する |
| 2 | 他の PC の常駐ウイルス対策が違う | 展開した本体を押さえると、**Run のあと何も起きない**形になる。この PC は Defender のみ |
| 3 | 他の PC の SmartScreen の設定・Windows の版 | 止め方が変わる |
| ~~4~~ | ~~回線が無い~~ | **消えた。**Release から落とせている＝通信はできている |

**候補 1 が当たりなら、これは「あの PC が壊れている」話ではない。**
**新しいビルドを配るたび、最初に実行した人が払う**ことになる。
**そして今回は、その支払いが終わらなかった。**

### ★ これを分ける 1 つ

**他の PC で、同じ setup をもう一度実行する。**

- **通る** → **候補 1 で確定。**1 回目で判定が取れた（または取れる状態になった）
- **また固まる** → **その PC の環境**（候補 2 / 3）。次はウイルス対策と SmartScreen の設定を見る

**どちらでも「ブロックの解除」は効く**（印を外すので、問い合わせの段に入らない）。

### 候補 1 だった場合の、署名の評価

- **EV なら効く**（最初から評判が付くので、誰も「最初の 1 人」にならない）
- **OV は効かない見込み**——評判はダウンロード数で積み上がるもので、
  **数人で使う用途では積み上がらない**
- **つまり「署名を買う」は実質 EV の話**になる。**買う前に費用を調べる**

### 違いの候補（旧・記録として残す）

| | 候補 | 根拠・考え |
|---|---|---|
| **1** | **この PC には既に評判（判定結果）がある** | この PC では**同じ系統の exe を何十回も実行している**（動作確認でインストール 6 回ほか）。SmartScreen は判定を**手元に覚える**ので、**問い合わせずに済む**。他の PC は**初めて**なので聞きに行く |
| **2** | **他の PC が問い合わせ先に届かない** | **届かなければ待つ。**回線が無い・社内のフィルタ・DNS が遅い、など。**「戻らなかった」はこれで説明が付く**（タイムアウトせず待ち続ける形） |
| 3 | 他の PC の SmartScreen の設定が違う | 「アプリとファイルの確認」が**ブロック**寄りだと止め方が変わる |
| 4 | 常駐のウイルス対策が違う | 展開した本体を押さえている可能性 |

**1 と 2 は両立する**（どちらも「問い合わせが要るかどうか」の話）。

### ★ 9/28 の再現は、実物と同じではなかった

**ここは正直に書く。**9/28 の確認では、

> **成果物は `curl` で取得しているので Mark of the Web が付きません。**
> **`Zone.Identifier`（ZoneId=3）を付けてから**実行しました。

**手で書いた `ZoneId=3`** を使っている。
**ブラウザが書く Zone.Identifier には `HostUrl` / `ReferrerUrl` も入る**ので、
**SmartScreen が見るものが違う**可能性がある。

つまり **9/28 の「Run を押したら進まない」は、合成した印による挙動だったかもしれない。**
**他の PC の事故は本物のダウンロード**なので、**同じ症状でも道筋が違いうる。**

**それでも「未了を丸めた」のは誤り**のままである——
**通せなかった段を開いたままにしておけば、他の PC の話を聞いたときに結び付けられた。**

### これを分ける 1 つ

**他の PC に普通のインターネット接続があるか。**

- **無い／塞がれている** → 候補 2 で決まり。**署名を買っても効かない**（評判は問い合わせるものなので）。
  **「ブロックの解除」だけが効く**
- **ある** → 候補 1 が主。**署名（特に EV）が効く**見込みがある

**ここが分かるまで、署名を買う判断はしない。**

## ★ 署名について（利用者に再度うかがう）

**2026-09-23 に「見送り」と決めたが、そのときの症状は「警告が出る」だった。**
**今回「固まって戻らない」が出たので、判断の前提が変わっている。**

- **年単位の費用がかかる**（具体的な額は、買うことになったら調べ直す）
- **OV と EV で効き方が違う。**EV は SmartScreen の評判が最初から付くが、
  OV は**ダウンロードが積み上がるまで警告が残る**——
  **この使い方（数人で使う）では OV の評判は積み上がらない**可能性がある。
  **買う前にここを確かめる**

## 元の切り分け表（記録として残す）

### こちらに残る問題（→ BUG-047 へ分けた）

`ShellExecuteExW` を **UI スレッドで同期的に呼んでいる。**

```
UI/FileListView.cs:1289          Activate（ダブルクリック / Enter）
  → Services/ShellContextMenuService.cs:51   ShellExecuteExW（SEE_MASK_INVOKEIDLIST）
```

**同じ呼び出しが 1 分以上返ってこないことを、2026-09-28 の確認で既に測っている**
（H-02。インストーラーに Mark of the Web を付けて実行したとき）。

> **「Run」を押したあと先に進めませんでした。**警告ダイアログは**不可視のまま生き続け**、
> **`ShellExecute` が 1 分以上戻らず**、セットアップのプロセスも起動しませんでした。

**そのとき「アプリ側の話ではないので持ち越さない」と判断した。それが誤り。**
あの観測は「`ShellExecute` は長く返ってこないことがある」という**仕組みの話**で、
**その仕組みを、こちらは UI スレッドで呼んでいる。**

**手前に `SHParseDisplayName` もある**（同じ関数の中）。あちらもシェルを触るので、
届かないパスでは待ちうる。

### これは BUG-043 / BUG-044 と同じ家族の 4 つ目

| | 面 | 状態 |
|---|---|---|
| BUG-038 / BUG-041 | アイコンを引く（一覧・タブ帯） | Fixed |
| BUG-043 | session の復元（起動時） | Fixed |
| BUG-044 | ツリーのノードのクリック | Fixed |
| **BUG-046** | **ファイルを開く（ダブルクリック / Enter）** | **ここ** |

**`grep Directory.Exists` では見つからない。**あちらはパスの確認で、
こちらは**シェルの実行**。**「UI スレッドから呼ぶと待ちうるシェルの関数」**という
括りで数え直す必要があった。

## 切り分け（利用者に確認中）

| 固まったのは | 原因 | 直し方 |
|---|---|---|
| **ExtendExprorer**（この一覧からダブルクリックした） | **こちらの `ShellExecuteExW` が UI スレッド** | 裏へ出す（ただし COM の都合を調べてから。下記） |
| **Windows のエクスプローラー** | **SmartScreen の評判問い合わせ**（未署名＋Mark of the Web）。こちらのコードは 1 行も走っていない | 署名を買う／ブロックの解除／`ExtendExprorer-win32-x64` の exe を直接使う |

**どちらでも上の「こちらの問題」は残る**ので、そこは別に直す。

## 直し方の候補（まだ決めない）

`ShellExecuteExW` を裏のスレッドへ出すのは**自明ではない。**

- `SEE_MASK_INVOKEIDLIST` は**コンテキストメニューのハンドラを呼ぶ**ので、
  **相手が STA の COM オブジェクト**でありうる。MTA の裏スレッドから呼ぶと挙動が変わりうる
- シェルの一部の verb は**メッセージポンプのあるスレッド**を要求する
- `ShellNamespace` / `ShellIcons` の MTA スレッドをそのまま使い回せるかは**調べていない**

**推測で入れない。**（`docs/win32-migration/dev-notes.md`
「推測を 1 往復ぶつけるより、判定材料を 1 往復で採る」）

  （Mark of the Web を外すと SmartScreen の問い合わせが起きない）
- または **`ExtendExprorer-win32-x64` の exe を直接置いて使う**（インストーラーを通さない）
