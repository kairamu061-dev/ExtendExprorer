# BUG-034: 旧版にあった見た目が 3 つ、新実装に移っていない

- **State**: Closed（2026-09-11 実機確認）
- **Reported**: 2026-09-09
- **Area**: win32-migration / tabs / pane-split /
  `src/ExtendExprorer.Win32/UI/TabStripView.cs`・`PaneView.cs`・`PaneHost.cs`・`MainWindow.cs`

## Summary

E2E の引き継ぎ 第 2 回で、**旧 WinUI 3 版にあって新実装に無いもの**が 3 つ見つかった。

1. **手前のペインを示す枠線が描かれていない**（pane-split E-04）
2. **非アクティブなタブのホバーで色が変わらない**（tabs E-24）
3. **タブを増やす「＋」が無い**（tabs E-27）

**どれも落ちない。**タブを増やす手段は `Ctrl+T` と右クリックメニューが残っていた。

## Reproduction

| | 観測（2026-09-09・`d640d04`） |
|---|---|
| 枠線 | 2 ペインで手前を左→右に切り替えて 2 枚撮り、画素で突き合わせ。**縦に長く続く線が 1 本も無い**（枠線があれば 700 画素前後の列が出る）。差の正体はフォーカス行の移動だけ |
| ホバー | `#F0F0F0` のまま。**同じ手でペイン帯の分割ボタンは `#FCFCFC` → `#E5F1FB` → `#FCFCFC` と変わる**ので、計測は効いている |
| 「＋」 | タブ帯の全面（739×23）を撮っても、**最後のタブの後ろに何も無い** |

## Expected

- 手前のペインだけ青い枠（旧版 `#0078D4`）、他は灰色
- 非アクティブなタブに乗せると `#E5F1FB`、離すと戻る
- 最後のタブの直後に「＋」。折り返していれば最終行の末尾

## Cause

**第 2 段（タブとペイン）の移植で落ちた。**どれも「描く」だけの機能で、
`tasks.md` の第 2 段の項目にも書かれていない——**移植の対象として挙がっていなかった**。

段階ごとの実機確認は**その段で新しく入れたもの**を見るので、
**「旧版にあったのに移植し忘れたもの」は、どの段の確認にも引っかからない。**
E2E の引き継ぎ表を作って初めて出てきた。

## Fix

### 枠線

**親（`MainWindow`）が描く。**ペインの中身は子ウィンドウ 4 つでできているので、
そのどれかに枠を持たせると 4 つの継ぎ目に線が入る。

`PaneView` が中身を**常に 1px 内側**へ置き（枚数で内側の広さが変わると、
分割のたびに一覧がずれる）、`WS_CLIPCHILDREN` の下でその 1px だけを親が塗る。

描き直す合図は 2 つ。**手前が変わったとき**と、**並べ直したとき**。
後者のために `PaneHost.Arranged` を足した——**仕切りのドラッグは親の
`WM_SIZE` を通らない**ので、それ以外に知る手が無い。
並べ直しは `ArrangeAll()` に一本化して、合図の出し忘れを起こさないようにした。

**ペインが 1 つのときは描かない。**「どれが手前か」を示す線なので、
1 つしか無いときは枠が増えるだけになる。

### ホバー

`WM_MOUSEMOVE` で覚え、`WM_MOUSELEAVE` で消す。
**`TrackMouseEvent` を頼まないと、帯の外へ出たときに色が残る**
（乗っていないのに乗って見える）。

- **手前のタブには出さない**（すでに白く、変化が読み取れない）
- **ドラッグ中は出さない**（挿入位置の線が主役で、背景まで変わるとどちらが結果か分からない）
- **並べ直したら番号を捨てる**。持ち越すと、次にマウスが動くまで違うタブに色が付く

### 「＋」

**折り返しの計算に、タブと同じ流れで乗せる。**幅の配列を 1 つ長くして
末尾を「＋」の幅にするだけ——最終行に入らなければ、自然に次の行の頭へ回る。

矩形は `_rects` と**同じときに組んで同じときに入れ替える**（BUG-031 の再入がある）。

押すと**手前のタブと同じフォルダ**で 1 枚増やす（旧版と同じ。履歴は引き継がない）。
**枚数の上限は設けていない**ので、旧版 E-28（50 枚で「＋」が消える）は移植しない。

- **Commit**: `1cdaf19`（枠の描き直しの取りこぼしを `b0f47f8` で修正）

**枠の無効化はペインごとの矩形ではなく、ペイン領域の全体で行う。**
`Arranged` が上がる時点で `PaneView.Bounds` はもう新しい位置を指しているので、
そこだけ無効化すると**古い枠が残る**。枠は子ウィンドウの**外側**の 1px にあり、
`MoveWindow` が無効化する「子が空けた領域」に入らない
（BUG-023 の「広がった分だけの無効化では古い絵が残る」と同じ形）。

### 確認結果（2026-09-11・`b0f47f8`）

| | 実測 |
|---|---|
| 枠線 | 2 ペインで手前を切り替え、**長い縦の列が 4 本**（x=1153 / 1519 / 1525 / 1891・各 755 画素）。手前 **`#0078D4`**・奥 **`#A0A0A0`**。1 ペインでは**しきい値を 50 画素まで下げても 0 本** |
| 枠線（並べ直し） | 仕切りを 180 画素動かして 1153 / **1340** / **1346** / 1891。**旧位置 1519 / 1525 に 1 本も残らない。**最大化でも同じ |
| 枠線（段階的に閉じる） | 2x2 → 3 → 2 → 1 の各段で走査。**2 ペインへ落ちた時点で縦の継ぎ目 1519 / 1525 が完全に消える**（ここが決定的な段） |
| ホバー | **`#E5F1FB`・912 画素**、当該タブの内側だけ。帯の外へ出すと 0。手前のタブは 0。**ドラッグ中は全区間で 0** |
| ホバー（番号の持ち越し） | 添字が範囲外になる形・カーソルの下に別のタブが来る形の**2 通りとも 0 画素**。描き残しなし |
| 「＋」 | 最後のタブの直後に **9x9 の十字が 1 個**。32 タブ・3 段（12/12/8）でも**十字は 1 個だけ**で、座標は**最終段** |

## Notes

- **判定の仕方は確認セッションが用意済み。**枠線は列ごとの差分、ホバーは
  `#E5F1FB` との比較、「＋」は帯の全面を撮るだけ
- **同じ取りこぼしが他にもありうる。**[e2e-coverage.md](../../docs/win32-migration/e2e-coverage.md)
  の「要」を潰しきるまでは、旧版を消さないこと
