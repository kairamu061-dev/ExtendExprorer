# BUG-041: タブ帯がアイコンを UI スレッドで引いている（BUG-038 の移植漏れの残り）

- **State**: Open
- **Reported**: 2026-09-29（コードレビュー指摘 1）
- **Area**: shell-icons / tabs（`UI/TabStripView.cs`・`Services/ShellImageList.cs`）

## Summary

BUG-038 第 2 段で**一覧**は「UI スレッドで実パスを引かない」にしたが、
**タブ帯はその経路に乗っていない。**
`TabStripView.LayoutTabs`（UI スレッド）がタブ 1 枚ごとに
`ShellImageList.IndexOfPath` を呼び、そこは `SHGFI_USEFILEATTRIBUTES` **なし**で
`SHGetFileInfoW` を呼ぶ＝**実パスを触る**。

あわせて **`ByPath` には上限が無かった**。

## Reproduction（未確認）

`--diag` で起動 →**切断されたネットワークドライブ**のフォルダを開いているタブを含む
セッションを復元。**タブ帯のレイアウトで固まるか。**
`[icon]` の行に**タブ帯ぶんが 1 件も計上されない**ことも併せて見える。

ほかに効きうる場面: スリープ中の USB、初回起動でタブを 10 枚まとめて復元。

## Expected

タブ帯のレイアウトが、実パスの応答を待たないこと。

## Cause

`IndexOfPath` の doc は

> 数が少なく（ドライブの台数＋1）増えないので、そのまま覚えておく

としていたが、**この前提は 2026-09-18 にタブ帯が呼ぶようになった時点で崩れていた。**
`ByPath` は `ByFile` の `MaxFileCache`（2048）に相当する上限を持たず、
**開いたフォルダの種類だけ単調に増える**——30MB 要件のあるアプリで、
**無制限に増える辞書はここだけ**だった。

## Fix

**2 つに分ける。上限だけ先に入れた。**

### 入れた: `ByPath` の上限

`ByFile` と同じ **2048** で打ち止めにして、越えたら捨てて作り直す。

- **Fix commit**: （このコミット。上限のみ）

### 残り: 裏で引く形に寄せる（**未着手**）

`PerFileIndex` と同じく「その場ではフォルダの既定を返し、裏で引いて `Resolved` で描き直す」へ。
**仕組みは既にある**（BUG-038 第 2 段の `ShellIcons` スレッドと `Resolved`）ので、
`IndexOfPath` をその経路に乗せ、タブ帯が `Resolved` で並べ直せばよい。

**いま入れないのは、`6de55a0` の確認がまだ済んでいないから。**
同じ回に 2 つ目のアイコンの変更を重ねると、どちらが効いたのか分けられなくなる。
