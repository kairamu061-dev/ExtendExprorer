# BUG-037: ペインを右へずらすと、隣のペインの絵が複製されて残る

- **State**: Fixed（実機確認待ち）
- **Reported**: 2026-09-19
- **Area**: win32-migration / layout / `src/ExtendExprorer.Win32/Interop/Win32.cs` ほか

## Summary

左右に分割した状態でフォルダビューを**開く**と、**右のペインの一覧の左端に、
以前の絵がそのまま残る。**幅は移動量ぶん、高さは一覧の全体。

**矩形はすべて正常。画面だけが古い。**そのため
「矩形が合っているか」で見ていた確認では **3 ラウンド見落としていた**
（V-01 / W-01f を「OK」と報告していたが、どちらも誤り）。

**消えない。**待っても、クリックしても、窓を 1px リサイズしても残る。
強制的な再描画か、最小化 → 復元でだけ消える。

## Reproduction

1. 左右に 2 分割する
2. ツリーを**畳む**
3. ツリーを**開く** ← ここで壊れる
4. 右ペインの一覧の**左端**を見る

**開くときだけ。**畳むときは 7 回測って毎回きれい。

### 実測（2026-09-19・窓の相対座標）

| 操作 | 右ペインの描き残し |
|---|---|
| 畳む | **0 px** |
| **開く** | **17124 px** — bbox `x 592..678`（**幅 87px・一覧の全高**） |

3 分割で 4 回繰り返し、**4 回とも 1 画素まで同一**。

| | 畳んだとき | 開いたとき | 移動量 | 描き残しの幅 |
|---|---|---|---|---|
| pane0 | 909 | 1085 | +176 | 0（※） |
| pane1 | 1404 | 1492 | **+88** | **87 px** |
| pane2 | 1651 | 1695 | **+44** | **43 px** |

※ pane0 が空けた帯は、開いたツリーと仕切りが必ず覆う。**見えないだけで、判定できない。**

| 構成 | 結果 |
|---|---|
| 1 ペイン | 起きない |
| 上下分割（左端が動かない） | 起きない |
| 左右 2 分割 | pane1 が乱れる |
| 左右 3 分割 | pane1・pane2 が乱れる |

**`c612200` でも画素まで同一。**BUG-036 の修正とは無関係で、以前からあった。

## Cause

**`MoveWindow`（＝ `SetWindowPos` で `SWP_NOCOPYBITS` 無し）が、
画面上のビットをそのまま新しい位置へ複製していた。**

ペインは**左から順に**置く。全体が右へずれるとき（ツリーを開く等）、
各ペインは**まだ動いていない隣のペイン**が写っている領域へ入っていく。
そこを複製したうえ、**その範囲は「正しい絵がある」と見なされて描き直されない。**

観測がすべて説明できる。

- **残った帯の幅＝移動量**（複製がずれた量そのもの）
- **左へ動く方向では起きない**（移動先は自分が空けた領域なので、複製しても正しい）
- **1 ペイン・上下分割では起きない**（左端が動かない＝複製のずれが無い）
- **消えない**（無効化されていないので、誰も描き直さない）
- **もう一度畳むと、描き残しがペインについて回る**（複製された絵ごと運ばれる）

## Fix

**並べ直しの移動をすべて `SWP_NOCOPYBITS` にした**（`Win32.MoveWindowNoCopy`）。

**複製そのものを止める**ので、「どのペインが壊れるか」を説明できなくても直る。
確認セッションが「規則にできなかった」と正直に書いてくださった小さな経路
（仕切りのドラッグ・ツリー幅・窓の拡縮で幅 1〜3px の筋）も、同じ仕組みなら一緒に消える。

移動のたびに描き直すことになるが、対象はペインの子（タブ帯・ナビ帯・一覧・仕切り）で、
一覧は二重バッファ付き。**正しさを優先する。**

あわせて、動いた量を `--diag` に残す（**左端が変わったときだけ**）。

```
[pane] 移動 1404,138-1644,891 -> 1492,138-1688,891（横に +88）
```

- **Commit**: `8f886cc`（移動の複製を止める）／`192a51b`（**外枠の描き残し**）

### 確認結果（2026-09-20・`8f886cc`）— 移動の経路はすべて 0 px

| 経路 | 前回 | 今回 |
|---|---|---|
| 左右 2 分割・ツリー開閉 ×4 | 3944 / 17124 px | **0（4/4）** |
| 左右 3 分割・ツリー開閉 ×4 | pane1 3944 / pane2 769 px | **0（4/4）** |
| 仕切りのドラッグ ×6 | pane2 2061 px | **0（6/6）** |
| ツリー幅 ±50 ×6 | pane1 1399〜2061 / pane2 687 px | **0（6/6）** |
| 窓の拡縮 ±100 ×12 | 3 分割の pane2 に 850〜1527 px | **0（12/12）** |
| 最大化 / 復元・上下分割・2×2・1 ペイン | — | **0** |

**感度は落ちていない**——前回 17124 px が出た配置（同じ窓・同じツリー幅・
右ペイン `C:\Windows` 109 件）をそのまま作り直したうえで測られている。

**「規則にできなかった」3 経路も 0 になった。**
どのペインが壊れるかを説明できないまま原因（複製）を潰した判断が当たっていた。

### 残っていた 2 画素（`192a51b` で対処）

```
[split] pane1 STALE = 2 px  bbox x 608..608 y 802..803
```

**縦分割で新しくできたペインだけ**（上下分割・ペインを閉じるは 0）。
場所は**一覧の横スクロールバーの左矢印の先端**（`#929292` / 正しくは `#F0F0F0`）。

**`SWP_NOCOPYBITS` が捨てるのは中身だけで、外枠は対象外。**
ペインの子は**大きさ 0 で作ってから**並べ直しで広げるので、
**外枠が一度も描かれていない状態**で置かれていた。

作った直後に 1 回だけ `RDW_FRAME` 付きで描き直す。
**移動の経路は 0 px で通っている**ので、生成の側だけを直した。

> 前回の描き残しとは**性質が違う**。あちらは 1px リサイズでもツリー開閉でも消えなかったが、
> こちらは**次に何か描き直しが起きれば消える**（確認セッションの切り分け）。

## Notes

- **レイアウトの正しさには「矩形」と「画素」の 2 つの出口がある。**
  こちらも確認する側も、**矩形しか数えていなかった**
- 確認セッションの測り方が決め手だった——
  **画面 → 強制再描画 → 画面の差**。アプリがどう描いているかに依存しない。
  さらに**最小化 → 復元でも同じ画素**が変わることまで確かめて、道具側の疑いを潰している
- 関連: [BUG-036](./BUG-036.md)（同じ「ツリーを開閉すると乱れる」に見えるが**別物**。
  あちらは矩形が狂う・1px リサイズで直る、こちらは矩形は正しい・リサイズでも直らない）
