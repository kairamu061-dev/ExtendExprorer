# BUG-013: 正式(Native AOT)ビルドが起動直後にクラッシュする

- **State**: Fixed（原因の断定はできておらず、実機での再確認待ち）
- **Reported**: 2026-08-04
- **Area**: build / aot（`ShellIconCache` / `PanelSplitter`）

## Summary

成果物 `ExtendExprorer-win-x64`（Native AOT）が、起動してウィンドウが表示された数秒後（6〜8 秒）に
100% クラッシュする。JIT ビルド（`ExtendExprorer-win-x64-jit`）は同じ操作で完全に安定しており、AOT 固有。

## Reproduction

1. `ExtendExprorer-win-x64`（AOT）を展開して起動する
2. ウィンドウは表示されるが、6〜8 秒でプロセスが消滅する（3 回中 3 回）

- Application Error: `Faulting module name: Microsoft.UI.Xaml.dll` / `Exception code: 0xc000027b`（STOWED_EXCEPTION）
- WER: `P7: 80004002`（`E_NOINTERFACE`）
- クラッシュダンプ: `%LOCALAPPDATA%\CrashDumps\ExtendExprorer.exe.*.dmp`

## Expected

AOT ビルドでも JIT と同じく安定して動作する。

## Cause

**断定できていない。** 開発環境が Linux で AOT を実行できず、実機でのバイセクトも未了。
既知の範囲は「`566d953` は AOT 正常 → `d4d59f3` でクラッシュ」。この区間には次が含まれる。

| 変更 | AOT 上のリスク |
|------|----------------|
| `d93f3be` アイコンキャッシュ（BUG-010） | **キャッシュヒット時に Task が同期完了**し、`Icon` の getter＝XAML のバインド評価中に PropertyChanged が発火して**バインドへ再入**する。WinUI 内部の状態を壊しうる。タイミング依存なので JIT では顕在化しにくい |
| `2b255a3` タブのアイコン（BUG-011） | 上の再入が `TabView` の項目実体化中に起きる経路 |
| `7d40122` `PanelSplitter` | **独自型を XAML から生成**している。AOT では型情報の解決に失敗しうる |
| `3ad1947` 自然順ソート | P/Invoke のみ。`E_NOINTERFACE` とは症状が合わない |
| `0751c8d`〜`d4d59f3` アイコン（ラスタ→ベクター） | 検証者の第一容疑。ただし標準の XAML 型のみ |

## Fix

**確度の高い順に 2 つ潰した**（どちらも単独で意味のある修正）。

1. `ShellIconCache.GetAsync` がキャッシュヒットでも**必ず一度制御を返してから**結果を渡すようにした
   （`AlreadyResolvedAsync`）。バインド評価中の再入がなくなる
2. `PanelSplitter` を XAML 生成からコード生成に変更し、`internal` へ戻した

- **Fix commit**: `3676a40`

## Notes

- **バイセクト用のビルドを用意した**（タグ＋workflow_dispatch）。上記で直らない場合はこれで切り分ける。

  | タグ | 内容 | クラッシュしたら |
  |------|------|------------------|
  | `aot-bisect-a` (`b61a2a0`) | BUG-010/011/012＋自然順まで | 原因は上記 1（アイコンキャッシュの再入） |
  | `aot-bisect-b` (`d68ac4d`) | ＋ ツリー幅（`PanelSplitter`） | 原因は上記 2 |
  | `aot-bisect-c` (`677b0ec`) | ＋ 新アイコン（ラスタ） | 原因は画像読込（ms-appx） |
  | いずれも正常 | — | 原因はベクター化（`d4d59f3`） |

- 2026-07-30 の検証で報告された「初回起動で 1 回だけ静かに終了」は、同じ問題の低頻度の現れだった可能性がある。
- 今回の検証はすべて JIT で行われているため、**AOT が直ってから各項目を AOT で再確認**する必要がある。
