## ★ ファイル操作を測るときの手順（2026-10-21 に確立。弱い方法に戻さないこと）

**これらは検証セッションが作った方法で、前の回より強い。**
`agent-rules.md`「より強い方法を使われたら、手順の側へ移す」に従ってここへ移した。

### ★ 1. 観測は「ファイルが消えてから」さらに 45 秒続ける

**固まるのはファイルが消えたあと。**最初の 3 回は「旧ビルドも固まらない」と出たが、
**観測を止めるのが早すぎただけ**だった。

```
  0ms      削除を送る
  1.4 秒   シェルの進捗ウィンドウ(OperationStatusWindow)が出る
 15.0 秒   ★ ディスクからフォルダが消える      ← ここで止めると固まりを丸ごと見落とす
 15.3 秒   ★ UI スレッドが返事をしなくなる
 32.2 秒   返事が戻る（進捗ウィンドウは 33.4 秒まで残る）
```

> **「操作が終わった」をファイルの有無で判定してはいけない。**

### 2. 観測は**別プロセス**から

固まっている相手を自分のプロセスから覗くと、こちらも一緒に止まる。

### ★ 3. 「窓が無効か」は `IsWindowEnabled` で測る

**メッセージを送らずスタイルを読むだけ**なので、**UI スレッドが塞がっていても返る。**
`Ping-UI`（往復）と並べて取ると、**(a) と (b) がそのまま分かれる。**

→ **前回「踏めず」で残した W-03「ボタンが押せるか」は、これで測れる。**

### ★ 4. 前面ガードは「プロセス一致」ではなく「主ウィンドウの hwnd 一致」で

**シェルの進捗・衝突ダイアログは、いまやこのアプリと同じプロセスのウィンドウ。**
プロセスしか見ないガードは**それらが前面のときも通してしまい**、
`Enter` や `Delete` が**キャンセル／置換／スキップのボタンに当たる。**
実際に 2 回、ガードが止めている。

### ★ 5. 主ウィンドウの hwnd は起動直後にラッチする

操作中は `Process.MainWindowHandle` が **`OperationStatusWindow` を返す**ので、
ペインを数える道具が全部そちらを見て「行が無い」という**嘘の結果**になる
（ドラッグ中の影ウィンドウと同じ罠）。

### 6. BUG-048 のような「隙間」を踏むとき

**隙間は 45ms しかない。**ガードは 1 回だけ通し、**2 つのキーを続けて送る**
（`Get-Process` を呼ぶガードは 1 回で数十 ms 食う）。
**踏めなければ「隙間を作れなかった」と書く。合格にはしない。**
