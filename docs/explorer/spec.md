# explorer 仕様

## 機能一覧

| # | 機能名 | 説明 |
|---|--------|------|
| 1 | ファイル一覧表示 | タブに指定フォルダの内容（名前・更新日時・種類・サイズ）をテーブル表示する |
| 2 | フォルダナビゲーション | ダブルクリックでフォルダに移動、「上へ」「戻る」「進む」で履歴移動する |
| 3 | タブ管理 | ペイン内でタブの追加・切替・クローズができる。「＋」ボタンでアクティブタブを複製する |
| 4 | 画面分割（ペイン管理） | ペインを縦・横に分割/削除でき、スプリッターでサイズ調整できる |
| 5 | アドレスバー | 各ペイン上部にアクティブタブのフォルダパスを表示し、パス入力で直接移動できる |
| 6 | セッション保存・復元 | 終了時にペイン構成・タブ・パス・アクティブ状態を保存し、次回起動時に復元する |

## 画面・操作フロー

1. アプリを起動する → 前回のセッションがあれば復元、なければホームフォルダを開いた 1 ペイン 1 タブで表示
2. ファイル一覧のフォルダをダブルクリックする → そのタブがフォルダ内に移動し、アドレスバーが更新される
3. タブバーの「＋」ボタンを押す → アクティブタブと同じパスの新しいタブが右隣に開き、アクティブになる
4. メニューまたはショートカットで「分割」を実行する → アクティブペインが分割され、新ペインに同じパスのタブが開く
5. アドレスバーにパスを入力して Enter → アクティブタブがそのパスに移動する
6. アプリを閉じる → 現在の状態が自動保存される。再起動すると手順 1 で復元される

## 各画面 / 状態の詳細

### メインウィンドウ

- **表示内容**: 1 個以上のペインを分割レイアウトで表示。各ペインは「タブバー」「アドレスバー」「ファイル一覧」で構成
- **操作**: ペインのクリック（アクティブペイン切替）、スプリッターのドラッグ（サイズ調整）、分割の追加/削除
- **遷移先**: なし（単一ウィンドウ）

### ペイン

- **表示内容**: タブバー（開いているタブ＋「＋」ボタン）、アドレスバー、アクティブタブのファイル一覧
- **操作**:
  - タブクリック → アクティブタブ切替
  - タブの**中クリック**、またはタブ上の**右クリックメニュー**→ タブクローズ（最後の 1 タブを閉じたらペインを閉じる。最後のペインの場合はホームのタブを開き直す。「×」ボタンは 2026-08-09 に廃止）
  - 「＋」→ アクティブタブの複製
- **遷移先**: なし

### ファイル一覧

- **表示内容**: フォルダ→ファイルの順で、名前・更新日時・種類・サイズを表示。列ヘッダクリックでソート
- **操作**: シングルクリック（行選択）、フォルダのダブルクリック（移動）、ツールバーの「上へ」「戻る」「進む」
- **遷移先**: 同一タブ内でのパス変更

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| 存在しないパスを入力 | アドレスバー下に「パスが見つかりません」を表示し、移動しない |
| アクセス権のないフォルダ | 一覧領域に「アクセスが拒否されました」を表示。タブは維持 |
| セッション内のパスが復元時に存在しない | そのタブはホームフォルダで開き、通知を表示 |
| セッションファイルが破損 | 既定状態（1 ペイン 1 タブ、ホーム）で起動 |

### 追加分（2026-10-21: 右クリックの「削除」を横取りする）

**2026-10-21 の確認で、右クリック経由だけが固まることが実測された**
（15 万件で `Delete` キー 0 回／右クリック 98 回のタイムアウト・15.9→33.0 秒）。
**利用者のご判断で、横取りする形にした。**

| # | 内容 |
|---|------|
| 1 | シェルのメニューで**動詞が `delete`** なら、`InvokeCommand` に渡さず **`ShellFileOperations.Delete`（別スレッド）へ回す** |
| 2 | ★ **差し替えているのではなく、呼ぶスレッドを変えているだけ。**横取り先も `IFileOperation` で、ごみ箱・確認・進捗はシェルが出す |
| 3 | ★★ **メニューからの削除は必ずごみ箱。`Shift` を見ない。**このメニューは `CMF_EXTENDEDVERBS` を渡していないので**「完全に削除」が出てこない**。なのに実行時の `Shift` を見ると、**「削除」と書かれた項目を押しただけで完全削除になる**——**ラベルと動作が食い違う** |
| 4 | ★ **「メニューを組む時」と「選ばれた時」は別の瞬間。**シェルは `QueryContextMenu` の時点の `Shift` で項目を決めるが、こちらが動詞を見るのは `TrackPopupMenu` が**戻ったあと**（利用者はもう離している）。**押した瞬間の修飾キーで、組んだ瞬間の意味を推し量ってはいけない** |
| 5 | **完全削除は `Shift+Delete` キーだけ。**あちらは `WM_KEYDOWN` の中なので、読んだ `Shift` が**その操作そのもの**。確認は `IFileOperation` が出す |
| 6 | **既定はごみ箱**（`FOF_ALLOWUNDO` あり）。取り返せない側を既定にしない |
| 7 | 前例は「名前の変更」——既に同じ形で横取りしている |

**コピー・切り取りは横取りしない。**クリップボードに置くだけで即座に終わるので、
**測った利点が無いのに確かめ済みの振る舞いを動かすことになる**（`Rename` と同じ判断）。

**貼り付けも横取りしない**（背景のメニューのぶんは従来どおりこちらで実行）。
項目のメニューの貼り付けは**右クリックされたフォルダが宛先**で、
いまの作りはその宛先を持っていない。**宛先を間違えるくらいなら触らない。**

**ご要望**: 「遷移中のタブ内のクリックはそもそも無視したい」「クリックは誤クリックとかあるから対応必要」。

| # | 内容 |
|---|------|
| 1 | **遷移中（行が差し替わる予定がある間）は、一覧のダブルクリック／`Enter` で開かない** |
| 2 | ★ **「遷移中」の終わりは差し替え完了（`Apply`）。**読み込み完了（列挙が終わった時点）ではまだ古い行が並んでいて、**利用者が見ている行とクリックが指す行が食い違う**時間が残る（3000 フォルダの `sub01` ではその隙間が広い・実測） |
| 3 | ★★ **アイコンの読み込みは待たない。**入れると BUG-045 の「アイコンが約 42 秒出ない」あいだ**クリックが丸ごと死ぬ**。行の確定はアイコンより先に終わる（2001 行が 10ms・3000 フォルダで世代が 100ms 以内に進む・実測） |
| 4 | ★ **止めるのは起動だけ。**選択・スクロール・右クリック・キー移動・ドラッグは通す。選択は差し替えで捨てられる（別フォルダへは引き継がない）し、**スクロールバーは一覧の窓の一部**なので、クリックを丸ごと飲むと掴めなくなる |
| 5 | `--diag` に **`[list] 遷移中なので開かない 行=N 経過=Nms`** を残す。経過も出すのは、**届かないネットワークのパスでここが数十秒 true になりうる**ため（列挙が返ってこない・BUG-043 の家族）。そのあいだ**戻る・アドレス欄・ツリー・タブは効く** |
| 6 | **BUG-049 の世代判定は残す。**あちらは「1 打目と 2 打目が差し替えをまたいだか」で、こちらは「差し替えの前か」——**別の窓**を塞いでいる |

### ★ これで**直らない**範囲（E-119）

**差し替えが済んだあとのダブルクリックは、今までどおり開きます。**
「遷移中」の終わりを差し替え完了に取った結果なので、**ご判断どおりの帰結**です。

**遷移中の貼り付け（E-84）は対応不要**とのご判断
（**誤操作ではなく意図した操作だから**）。いまの実装では**止めていません**——
起動だけを止める形なので、貼り付けは通ります。

## 追加分（2026-10-23: ダウンロードは更新日時の降順で開く）

| # | 内容 |
|---|------|
| 1 | **ダウンロードフォルダを開いたときの並び順の既定を「更新日時の降順」**にする（新しいものが上）。それ以外のフォルダは今までどおり**名前の昇順** |
| 2 | ★ **ダウンロードの場所は OS に聞く**（`FOLDERID_Downloads`）。**移せる**ので決め打ちにしない |
| 3 | ★ **「フォルダを先頭にまとめない」（2026-09-18）と同じ判定を使う。**2 つの既定は**同じ 1 つの理由**（そこに落ちてくるものは新しいかどうかで探される）から出ているので、判定を 2 か所に書かない |
| 4 | **覚える仕組みは付けない。**並び順は**タブ**が持っていて、移動すると既定に戻る——元からの作り。**変えたのはその「戻る先」だけ** |
| 5 | 見出しをクリックして並べ替えれば、**そのタブではそれが続く**（今までどおり） |
| 6 | **セッションから復元したタブは、前回の並び順をそのまま使う**（タブが覚えているものが優先。今までどおり） |

### ★ あわせて直した seam

**並び順の既定を決める場所を `Load` から `Apply`（行の差し替え）へ移した。**
`FoldersFirst` を BUG-048 で移したのと同じ理由で、
**`SortColumn` は「並んでいる行がどう並んでいるか」を表す値**だから。

`Load` で決めていると、遷移中に次の 2 つが壊れる（**見出しの矢印ではない**——
あれは差し替えのときしか描き直さないので、遷移中は古いまま正しい）:

- 遷移中に見出しをクリックすると、**同じ列と判断して昇降を反転するだけ**になる
- 遷移中にタブを控えると、**まだその順に並んでいない列**を覚える

**ダウンロードの既定を変えたことで、移動の前後で列が実際に変わるようになり、
この seam が意味を持つようになった。**
