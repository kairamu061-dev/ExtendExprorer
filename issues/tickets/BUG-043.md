# BUG-043: 届かないネットワークパスのタブが session にあると、起動が約 21 秒止まる

- **State**: Fixed
- **Reported**: 2026-10-03（動作確認フィードバックで発見。**今回の変更とは無関係の既存不具合**）
- **Area**: session / pane-split（`UI/PaneHost.cs`）

## Summary

session に**到達しないネットワークパスのタブ**が 1 枚あると、
**窓が 1 つも出ないまま約 21 秒止まる。**

- **手前でないタブでも効く**（見えてすらいないタブ 1 枚で 21 秒）
- **直列。**2 枚なら **42 秒**
- **新旧で差が無い**＝今回の変更で入ったものではない

## Reproduction

```
旧 a900035（\\192.0.2.11\share\x を含む session）  窓が出るまで 21,850ms
新 adb5ac2（\\192.0.2.12\share\x を含む session）  窓が出るまで 21,262ms
対照: 同じ session からそのタブだけ外す              窓が出るまで    297ms
```

- アドレスは TEST-NET-1（`192.0.2.0/24`。到達しないことが保証された帯域）
- **ビルドごとに別のアドレス**を使う（SMB の失敗キャッシュで 2 回目が速くなるのを防ぐ）
- **入力は一切送っていない**（session を置いて起動しただけ）
- 窓が出たあとの応答は正常（最大 15ms / 26ms・タイムアウト 0）

## Expected

**窓はすぐ出る。**開けないフォルダのタブは、**選ばれたときに**エラーになる。

## Cause

`PaneHost.RestoreTabs` が**タブごとに `Directory.Exists(path)` を呼んでいた。**

```csharp
if (string.IsNullOrEmpty(path) || (!special && !Directory.Exists(path)))
{
    state.Missing = true;
    continue;       // 「無くなったフォルダは開かない」
}
```

- `Directory.Exists` は **UNC なら SMB の接続待ち**に当たる。到達しなければ約 21 秒
- **`Restore` は `window.Create` と `window.Show` の間**にある（`Program.Main`）。
  だから**窓が出る前**に止まる
- ループなので**直列**

> **「存在を確かめる」こと自体が、ディスク（SMB なら NIC）を叩く。**
> 依頼書に自分で書いた原則——**避けられない仕事なら UI スレッドから外す**——を、
> **起動経路には当てていなかった。**アイコンでは 2 度やったのに。

## Fix

**確かめるのをやめた。**開けないフォルダのタブも**そのまま復元**し、
**選ばれたときに**ふつうの非同期の読み込みが失敗して
「パスが見つかりません」の板を出す（その道は既に確認済み）。

**起動時のパスへの I/O が 0 になる。**

- **これができるのは [BUG-041](./BUG-041.md) のあと。**
  タブ帯の絵が同期のままだと、ここを直しても**帯の方で止まっていた**
- **Fix commit**: （このコミット）

### 挙動が変わるところ（意図）

| | 前 | 後 |
|---|---|---|
| 消えたフォルダのタブ | **黙って消える** | **残り、選ぶと「パスが見つかりません」** |
| 届かないネットワークのタブ | **起動が 21 秒 × 枚数 止まる** | **すぐ起動する。**選ぶとエラー |

**黙って消す方が良い、とは言えない。**前者は**利用者のタブが無断で失われる**形で、
`[session] 開けなかったフォルダがあった` の 1 行しか残らなかった。

## Notes

- **`Program.FirstTabPath` にはまだ `Directory.Exists` が残っている。**
  あちらは `--panes=N` を付けて session のレイアウトを使わないときだけ通る道
  （実測・再現用）なので**今回は触らない**。普段の起動では通らない
- **`Program.StartPaths`** の確認は残す。**利用者がコマンドラインに書いたもの**なので、
  そこで待つのは筋が通っている
- 「切断された割り当てドライブ（`Z:` など）はもっと速く失敗するかもしれない」と
  報告されている。**そちらは踏めていない**
