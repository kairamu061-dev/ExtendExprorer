# プロジェクト概要

## 目的・背景

Windows 11 標準のエクスプローラーはタブ機能を持つが、画面分割（複数ペイン同時表示）や柔軟なセッション復元ができない。
本プロジェクト「ExtendExprorer」は、Tablacus Explorer のようなマルチタブ・マルチペイン型のファイルエクスプローラーを Windows 11 向けに提供し、複数フォルダを同時に見ながらのファイル整理作業を効率化する。

動作の軽さとメモリ使用量の節約を重視し、Web ランタイムを使わないネイティブ実装を採用する（当初 WinUI 3 → 2026-08-13 に素の Win32 ＋ Native AOT へ変更。「制約」節を参照）。

## スコープ

### 作るもの

- タブ型ファイルエクスプローラー（1 ペインに複数タブ）
- 画面分割（複数ペインの同時表示）
- 各ペインのフォルダパス（アドレスバー）表示
- アプリ終了時の状態保存と、次回起動時の復元（タブ・ペイン構成・各タブのパス）
- 「＋」ボタンによるタブの複製（現在のタブと同じパスで新規タブを開く）
- フォルダ内容の一覧表示と基本的なナビゲーション（ダブルクリックで移動、上へ、戻る/進む）

### 作らないもの

- リネームの自前 UI（インライン編集。将来検討 — コピー/移動/削除/貼り付けは 2026-07-19 にスコープ入りし、シェル IFileOperation 経由で提供）
- ネットワークドライブ・クラウドストレージの特別対応
- アドオン/プラグイン機構
- Windows 以外の OS への対応

## 技術スタック概要

| 技術 | 用途 | 選定理由 |
|------|------|----------|
| **素の Win32（comctl32 / shell32 を直接呼ぶ）** | UI フレームワーク | **メモリ目標 30MB を満たせる唯一の選択肢**（実測 25.7MB）。`SysListView32` 等の OS 標準コントロールをそのまま使うため、外観も操作感もエクスプローラーと同じになる |
| C# / .NET 8 **Native AOT** | アプリ実装全般 | ランタイムを積まないぶん軽い（実確保 6.8MB）。既存の ViewModel 層・シェル連携（`IFileOperation` 等の COM 相互運用）をそのまま持ち込める |
| System.Text.Json | セッション永続化 | 追加依存なしの JSON シリアライズ |

選定の経緯:

1. 当初 Electron を検討 → 軽量・省メモリ方針（ユーザ指示）により **WinUI 3** に変更（2026-07-04）。比較候補は Tauri / Wails / WinUI 3 / Electron
2. **WinUI 3 では目標に届かないことが判明**（機能の無い雛形で 114MB・参考ツールは 29MB）。
   メモリが「要件」に格上げされ（2026-08-12）、UI 基盤を **素の Win32 ＋ Native AOT** に載せ替え（2026-08-13 実測により決定）

> **WinUI 3 期の資産の扱い**: ViewModel 層・サービス層・シェル相互運用・仕様書・テストケース・
> チケットはすべて引き継ぐ。作り直すのは View（XAML）だけ。
> 旧実装は `src/ExtendExprorer`（載せ替え完了まで動く状態で残す）。

## 全体アーキテクチャ

単一プロセスの MVVM 構成。

```
[View]       MainWindow / PaneView / FileListView / AddressBar (XAML)
   │ データバインディング
[ViewModel]  MainViewModel（レイアウト木）/ PaneViewModel / TabViewModel
   │
[Service]    IFileSystemService（フォルダ列挙）/ ISessionService（状態保存・復元）
   │
[OS]         .NET File API / %LOCALAPPDATA%\ExtendExprorer\session.json
```

## 制約

- 実行ターゲット・開発環境ともに Windows 11（WinUI 3 は Linux 上で開発・ビルド・実行できない）
  - 本 devcontainer（Linux）ではドキュメント作成・コードレビューのみ可能。ビルドと動作確認には Windows + .NET 8 SDK + Visual Studio 2022（または `dotnet build` + Windows App SDK）が必要
- ファイルの編集操作（コピー/移動/削除/貼り付け）はシェル（IFileOperation・コンテキストメニュー）に委譲し、自前のファイル操作コードを書かない
- 配布は当面 unpackaged（exe 直置き）とし、MSIX 化は将来検討
- **メモリ使用量の目標: 起動直後 30MB 前後（2026-08-12 にユーザ指示で「要件」へ格上げ）**
  - 参考ツール（Tablacus, 複数タブ・複数エリアで **29MB** 実測）と同等を目指す
  - **WinUI 3 ではこの目標に届かない**（機能の無い雛形の時点で 114MB・dev-notes 参照）。
    したがって UI 基盤の載せ替えが前提となる。「コストはかかってよい」との判断（同日）
  - 載せ替え先は実測で決めた（`spikes/` と `.github/workflows/spike.yml`・2026-08-13 実測）。
    **結論: C# / Native AOT ＋ 素の Win32（XAML なし）。ViewModel 層・シェル連携・仕様/チケットは移植する**

### UI 基盤の実測（2026-08-13・ホーム表示時）

| 基盤 | ワーキングセット | **コミット（実確保）** |
|------|------------------|------------------------|
| **C# AOT ＋ 素の Win32**（採用） | **25.7MB** | **6.8MB** |
| C# WinForms（JIT） | 52.0MB | 12.3MB |
| WinUI 3（現行・AOT） | 136.2MB | 116.9MB |

- 判断の決め手は**コミットサイズ**。6.8MB 対 116.9MB＝**約 17 倍**で、
  「マップ済み DLL の見かけ上の差」ではなく**実際に確保しているメモリの差**。載せ替えれば本当に減る
- WinForms は素の Win32 より +26MB 重く、目標 30MB に届かない（AOT 非対応で JIT ランタイムが戻るため）
- 見た目は `SysListView32` をそのまま使うため**エクスプローラーそのもの**になり、
  「エクスプローラーに似せる」という UI 方針とも一致する（WinUI を手作業で Win32 風に寄せる必要が消える）
- ただし 25.7MB は**機能の無い雛形の床**。タブ・ツリー・ペイン・session 等を載せた後の実測は別途必要

## UI デザイン方針

### コンセプト

Tablacus Explorer 風の高密度・実用重視 UI。装飾より情報量と操作効率を優先する。
（参考スクリーンショット: 4 ペイン分割、各ペインにタブバー＋アドレスバー＋ファイル一覧）

見た目・操作感は **Windows 標準のエクスプローラーに似せる**（2026-07-13 ユーザ要望）:
ファイル/フォルダのアイコンはシェルの実アイコン、右クリックはシェルのコンテキストメニュー、
ダブルクリックは既定アプリで開く、左側にフォルダツリー、といった標準の作法に合わせていく。

### カラーパレット

ライトテーマ固定（`RequestedTheme=Light`）。サンプルツール（Tablacus）準拠のクラシック配色:
タブ帯・ツールバー・ツリーヘッダは #F0F0F0、列ヘッダ（ファイルバー）はそれより少し薄い #F7F7F7、
一覧・ツリーは白、境界線 #D0D0D0（2026-07-19〜20 ユーザ要望）。
タブ帯／ツールバー／アドレスバー／ファイルバーの各境界は #D0D0D0 の実線で区切る。
一覧の行は高密度（行高 22px・縦余白 0）でエクスプローラーの詳細表示に寄せる。
そのほかは WinUI 3 の標準テーマリソースを使い、固定色は最小限にする。

| 用途 | カラーコード | 説明 |
|------|-------------|------|
| プライマリ | SystemAccentColor | Windows 設定のアクセント色に追従（選択・アクティブタブ） |
| セカンダリ | SubtleFillColorSecondary | 選択行・ホバーの背景 |
| 背景 | LayerFillColorDefault | ペイン背景 |
| テキスト | TextFillColorPrimary | 基本テキスト |
| エラー | SystemFillColorCritical | エラー表示 |

### タイポグラフィ

- フォント: Segoe UI Variable（WinUI 既定）
- 基本サイズ 12–13px 相当（ファイル一覧は高密度表示）

### コンポーネント方針

- タブは**自作のタブ帯**（幅は名前に合わせ、入りきらなければ折り返す。「×」は置かず中クリック／右クリックで閉じる）
- ファイル一覧は仮想化された詳細表示（名前・更新日時・種類・サイズ）
- ペイン境界・ツリー境界は**自作のスプリッタ**でドラッグ可能（外部の GridSplitter は不採用）
