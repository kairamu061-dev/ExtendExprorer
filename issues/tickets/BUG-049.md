# BUG-049: 遷移の前にクリックした座標で、入れ替わったあとの行が開く

- **State**: Open（**対応方針のご判断待ち**）
- **Reported**: 2026-10-21（検証セッション。BUG-048 の確認中に派生）
- **Area**: `UI/FileListView`（`NM_DBLCLK` と `EntriesReset` の間）

## Summary

フォルダをダブルクリックして**一覧が入れ替わったあと**に、
**同じ座標をもう一度ダブルクリック**すると、**入れ替わった先の行が開く。**

実測では `D:\eetest\B\pad000001.txt` が**テキストエディタで開いた**——
利用者としては**フォルダを開こうとしていた**のに、別のファイルが起動している。

**[BUG-048](./BUG-048.md) とは別の症状。**あちらは「古い行の名前＋新しいパス」で
**存在しないパス**を組む話で、**修正済み**。こちらは**組み立てが正しいまま、
利用者が狙っていない行に当たる**。BUG-048 の修正では直らない。

## Reproduction

1. 列挙に時間のかかるフォルダを開く
2. 中のフォルダの行をダブルクリックする
3. **125ms 後**（＝一覧が入れ替わったあと）に、**同じ座標**をもう一度ダブルクリック
4. → **入れ替わった先の、その座標にある行**が開く（実測ではテキストファイル）

**隙間が 33〜78ms** なので、**それより遅ければ新しい一覧に当たる**（BUG-048 の確認で実測）。

## Expected

**まだ決まっていない。**下の「論点」を参照。

## Measured / Inferred

| | 測った（根拠） | 推測（何が分かれば決まるか） |
|---|---|---|
| 症状 | ★ **検証セッションが実測**（2026-10-21。`pad000001.txt` が開いた） | — |
| 原因 | **一覧の中身が入れ替わるのに、ポインタの位置は変わらない。**2 回目のクリックは**新しい行**に当たる。`EntriesReset` → `LVM_SETITEMCOUNT` で中身が差し替わることはコードから確認済み | — |
| 影響 | — | ★ **旧ビルドでも、Windows のエクスプローラーでも同じか、を確かめていない。**理屈の上では同じはず（パスの取り違えとは無関係なので）だが、**踏んでいない。**これが分かるまで「退行ではない」とは書けない |

> ★ **「エクスプローラーも同じだから問題ない」と書きたくなるが、それは推測。**
> 対照を取るまでは書かない。

## 論点（ご判断いただきたいこと）

**直すべきかどうかから決める必要がある。**

| 案 | 中身 | 代償 |
|---|---|---|
| **A: 何もしない** | 一覧の中身が変われば、同じ座標には別のものが来る——どの一覧でもそう | **意図しないファイルが起動する**ことが残る。「遅いときに限って起きる」ので、いちばん困るときに起きる |
| **B: 入れ替えた直後の短い間、起動だけ止める** | `EntriesReset` から N ms 以内の `NM_DBLCLK` を捨てる | **N の根拠が無い。**速い機械では邪魔なだけになる。**「勘で決めた定数」を 1 つ増やす** |
| **C: 1 回目のクリックの位置と行を覚えておき、入れ替わっていたら捨てる** | ダブルクリックの 1 打目の時点の世代を見る | 作りが増える。**ただし根拠は N ms より確か** |

**A と B と C のどれでも、まず「エクスプローラーはどうか」を測ってから。**
