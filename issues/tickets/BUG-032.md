# BUG-032: 読めないフォルダのペインが真っ白になる（エラーの文字も出ない）

- **State**: Closed（**不具合ではなかった**。2026-09-07）
- **Reported**: 2026-09-06
- **Area**: win32-migration / file-list / `src/ExtendExprorer.Win32/UI/FileListView.cs`

## Summary

読めないフォルダ（`C:\Windows\System32\config` で実測）を開くと、
**一覧が消えたうえに、エラーの文字も出ず、ペインが真っ白**になる。

**落ちない。**`error.log` も出ない。

## Reproduction

1. 読めないフォルダへ移動する（`UnauthorizedAccessException` を実測済み）
2. 一覧が丸ごと消える（`vis=False`・列の見出しも出ない）
3. **エラーの文言も出ず、ペインが真っ白**
4. 背景の右クリックメニューも出ない（＝「新規作成」までたどり着けない）

## Expected

「アクセスが拒否されました」が中央に出ること（旧版 [BUG-020](./BUG-020.md) で
そのように直し、2026-08-16 に確認済み）。

## Cause

**未特定。**外から見えているのは「一覧は隠れている・文字は出ていない」まで。

コードを読む限り、経路はこうなっている。

1. 列挙が `ListError(AccessDenied)` を返す → `ErrorMessage = "アクセスが拒否されました"`
2. `EntriesReset` → `UpdateMessage()`
3. `ErrorMessage` が非 null なら、一覧を隠して**文字の板**（`STATIC`）に文字を入れて出す

**一覧が隠れている以上、3 の分岐までは来ている**はずで、
そうであれば文字は入っているはずだが、出ていない。

考えられるのは、

- **(a)** 文字の板そのものが出ていない（作成に失敗している・大きさが 0）→ **第 1 回で消えた**
- **(b)** 出ているが文字が描かれていない（色・フォント・`WM_CTLCOLORSTATIC` の側）
- **(c)** そもそも別の理由で一覧が隠れていて、エラーは立っていない → **第 1 回で消えた**
- **(d)** **描かれているが、写真がその位置を写していない**（第 1 回のあとに増えた線）

**推測で直さない。**（[BUG-019](./BUG-019.md) / [BUG-020](./BUG-020.md) で
「読む限り正しいのに実機で効かない」を 3 回外している）

### 切り分け 第 1 回（2026-09-07・`847c03b`）

```
[list] 読み込み結果 C:\Windows\System32\config 件数=0 エラー=アクセスが拒否されました
[list] 文字の板=出す「アクセスが拒否されました」 板=1C10E8 件数=0
```

**(c) は消えた。**エラーは立っていて、板も 0 ではない。

板そのものを外から調べた結果（確認セッション）:

| 見たもの | 値 |
|---|---|
| クラス | `Static` |
| 文字 | `アクセスが拒否されました`（正しく入っている） |
| 表示状態 | `IsWindowVisible = True`・最小化なし |
| 位置と大きさ | `1535,169 - 1872,972`（**337 × 803**）＝ペイン全面 |
| スタイル | `0x50000201`＝`WS_CHILD`+`WS_VISIBLE`+`SS_CENTER`+**`SS_CENTERIMAGE`** |
| `WM_GETFONT` | NULL ではない |
| 親のスタイル | `WS_CLIPCHILDREN` が立っている |

→ **(a) も消えた。**「板が無い」「隠れている」「大きさ 0」「文字が空」
「フォントが無い」「親が塗り潰している」は全部違う。

### 色の線も消えている

同じ機械の `--diag` に、`[customdraw]` の行が繰り返し出ている。

```
[customdraw] … 薄色=727272 本文=000000 背景=FFFFFF
```

板の文字色は `FileListView.DimmedTextColor`＝この `727272`、
背景は `GetSysColor(COLOR_WINDOW)`＝`FFFFFF`。
**白地に白ではない。**（`WM_CTLCOLORSTATIC` が仮に届いていなくても、
`DefWindowProc` は本文色を返すので、どちらに転んでも文字は見えるはず）

さらに、旧 `win32第2段_拒否タブ表示_2026-08-16.png`（**窓全体**の写真）では
**この経路が正しく描けている**。

### 残っている分かれ道 — **写真が文字の位置を写していない可能性**

いただいた 2 枚は、いずれも**板の上端側だけ**を切り取ったもの。

| 写真 | 大きさ | 板 |
|---|---|---|
| `M-112c_読めないフォルダは真っ白.png` | 345 × **400** | — |
| `M-114_出しているのに描かれない.png` | 345 × **120** | 337 × **803** |

**`SS_CENTERIMAGE` は文字を縦中央に置く。**803px の板なら文字は
**上端から 400px あたり**にある。M-114 の 120px の切り取りには**入りようがない**。
こちらで PIL に通しても、2 枚とも（右端の枠線を除いて）200 未満の画素が 1 つも無い。

**ただし、これで決まったわけではない。**M-112c の 400px の切り取りは、
仮に板の上端から始まっているなら**文字の上端が数行かかるはず**で、
それも写っていない。つまり次のどれかで、まだ選べない。

- M-112c の切り取りの原点が板の上端ではなかった（原点は書かれていない）
- その回は板の大きさが違った（＝中央の位置も違う）
- **本当に描かれていない**

### 切り分け 第 2 回（この回で入れた）

**言葉で「中央を撮ってください」と頼むと、また外す。**
**どこを撮ればよいかをアプリ自身に言わせる**ことにした。

```
[list] 板の位置 画面 L,T-R,B 内側 W×H 文字 w×h → 文字はここ 画面 x1,y1-x2,y2
```

最後の矩形をそのまま切り取ってもらえば、framing の線は永久に消える。
**合わせて、板の全面（337 × 803）も 1 枚。**

### 決着（2026-09-07・`47f4b06`）

**文字は描かれていた。**アプリが出した座標と、実際に文字があった座標が一致する。

```
[list] 板の位置 画面 1073,196-1812,902 内側 739×706 文字 116×15
       → 文字はここ 画面 1384,542-1500,556
```

| | 値 |
|---|---|
| アプリの予告 | `1384,542 - 1500,556` |
| 実際に暗い画素があった範囲 | **`1385,542 - 1499,553`** |
| いちばん暗い画素 | **114**（＝`0x727272`＝`DimmedTextColor`） |

写真 `M-119a`（原点 `1344,502` / 196×94）に
**「アクセスが拒否されました」がはっきり写っている**。
板の全面（739×706）でも縦のほぼ中央に同じ文字。

**したがって (b) も (d) も「描かれている」で決まり、(d) が正しかった。**
前 2 回の「真っ白」は、どちらも**板の上端側だけを切り取った写真**で、
`SS_CENTERIMAGE` が文字を置く縦中央が入っていなかった。

## Fix

**不要。**コードは最初から正しく動いていた。
足したのは切り分けのための `[list] 板の位置 …` の 1 行だけで、これは残す
（同じ疑いが出たときに、また 2 往復しないため）。

## Notes

- **「背景の右クリックメニューが出ない」は本当に残っている。**板がペイン全面を
  覆っているので、右クリックは板に吸われる。ただし**読めないフォルダなので
  「新規作成」もどのみち失敗する**——実害が薄いため、別途起票して後回しにする
- **学び: 見えない／出ない系は、写真を撮る前に「どこを撮るか」をアプリに言わせる。**
  「真っ白」という報告を 2 回受け、こちらも 2 回とも真に受けかけた。
  決めたのは**アプリが出した矩形と、実際に画素があった矩形が一致した**という
  1 組の数字だけ。BUG-030（「漏れではなかった」）と同じ形——
  **外から測った値では、無いものと写っていないものを区別できない**
- 報告してくださった側から「切り取りの原点を書いていれば 1 回目で気付けたはず」
  という申し出があったが、**原点を求めなかったのはこちら**（依頼書に書いていない）。
  求めるものを決めるのは依頼書の側の責任として記録しておく
- 関連: [BUG-020](./BUG-020.md)（旧版で同じ表示を直した経緯。
  「項目が無いときの文字」は空になった最初の一度しか聞かれない、という罠がある）
