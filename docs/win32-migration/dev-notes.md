# win32-migration 開発メモ

## 実装上の判断

### 例外はウィンドウプロシージャの外へ出せない（第 1 段）

`[UnmanagedCallersOnly]` の関数からマネージド例外が抜けると、ランタイムが fail-fast して
プロセスが即死する。ダイアログもスタックも残らないため、**BUG-013（AOT 起動失敗）と
症状が見分けられない**。

そこで `WndProc` と `UiDispatcher.Drain` の中を try/catch で囲み、捕まえた例外は
`%LOCALAPPDATA%\ExtendExprorer\error.log` に追記する（`UI/Diagnostics.cs`）。
握りつぶすだけだと実機での原因が分からなくなるため、記録だけは必ず残す。

`LVN_GETDISPINFOW` は行番号を添えて呼ばれるが、読み直しの直後などに古い番号で
聞かれることがある。境界の外側だけでなく、**ハンドラの先頭でも行番号を検査**している。

### 素の Win32 には同期コンテキストが無い（第 1 段）

WinUI 版は `DispatcherQueue` で UI スレッドへ戻していたが、素の Win32 では `await` の
続きがスレッドプールで走ってしまう。ウィンドウを触ってよいのは作成したスレッドだけなので、
`UI/UiDispatcher.cs` を用意して、

- フォルダ列挙の結果
- `FileSystemWatcher` の通知

の両方をここ経由で UI スレッドに載せ替えている。投入は常にキューへ行い、ウィンドウが
まだ無い間は起こす通知だけ省く。`Attach` の直後に一度掃き出すので、**ウィンドウ作成前に
終わった初回読込を取りこぼさない**。

### アイコンは拡張子単位でキャッシュする（第 1 段）

移行の主目的（メモリ）に直結する部分。`SHGFI_USEFILEATTRIBUTES` を付けると実在しない
パスでも「その拡張子の既定アイコン」が返るので、**ディスクに触らずに**番号を引ける。
1 万件のフォルダでもシェルを呼ぶのは拡張子の種類の数だけになる。

例外は実行ファイルやショートカット（`.exe` `.lnk` `.ico` `.cur` `.ani` `.scr` `.msc` `.cpl` `.url`）で、
ファイルごとに固有のアイコンを持つため実パスで引く。

画像の実体は OS 側に置いたまま（`LVS_SHAREIMAGELISTS` で借りる）なので、項目ごとに
持つのは `int` ひとつも要らず、キャッシュ表だけで済んでいる。

### 選択は「行番号」で持たれている（第 1 段）

WinUI 版の選択はオブジェクトの同一性で保たれていた（`BuildEntries(reuse:)` が
同じインスタンスを使い回していたのはこのため）。オーナーデータの一覧は**行番号**で
選択を持つので、並べ替えや読み直しで行が動くと、そのままでは別のファイルが
選択された状態になる。

そこで、行が動きうる操作の前後で**名前を控えて付け直す**ようにした。
差分更新のうち、

- 追加（末尾）・リネーム（位置固定）→ 行番号が動かないので**付け直し不要**
- 削除 → それ以降がずれるので付け直す

としている。付け直しが要る箇所が削除だけで済んでいること自体が、
差分更新が本当に差分で動いている確認になっている。

### 並べ替えに名前での決着を入れた（第 1 段・仕様の明確化）

WinUI 版は `OrderBy`（安定ソート）だったため、同じ値の項目は列挙順のまま残っていた。
`List.Sort` は安定ではないので、**更新日時や種類が同じ項目の順が読み込みのたびに変わる**。
値が同じときは名前の自然順で決着させることにした。エクスプローラーの挙動とも一致する。

### 種類の列はシェルの表記に寄せていない（第 1 段）

アイコン番号と同時に `SHGFI_TYPENAME`（「テキスト ドキュメント」等、エクスプローラーと
同じ表記）もほぼ無料で取れるが、`docs/explorer/file-list/spec.md` は
**拡張子の大文字表記**と定めている。移行では仕様を動かさないのが原則なので、現行版の表記を保った。
シェルの表記に変えたい場合は別途相談する（移行が終わってからでも同じ手間で入る）。

### 実測 #1 で見えた「行ごとの微増」の正体（第 1 段）

System32（4838 件）を全行スクロールさせると WS が +8.5MB / コミットが +1.6MB 増え、
その後は頭打ちになる（2026-08-15 実測）。**リークではなく、増えているのは
システムイメージリストの中身**と考えている。

拡張子単位のキャッシュが効かないのは `.exe` `.lnk` など**ファイルごとに固有の絵を持つもの**で、
System32 には実行ファイルが数百ある。1 つずつシェルに聞くたびに OS 側のイメージリストへ
新しいアイコンが積まれ、その分の共有ページが自分のプロセスにも見える。
異なる絵の種類には限りがあるので頭打ちになる。

**画像そのものを抱えているわけではない**（旧 WinUI 版は 1 枚ずつ `WriteableBitmap` に
変換して保持していた）。第 2 段でタブ 30 枚にしても、同じ拡張子・同じ実行ファイルなら
同じ番号を引くだけなので、ここが積み上がることは無いはず。実測 #2 で確認する。

## 課題と対応

### 起動が「空のまま」になる罠

初回のフォルダ列挙がウィンドウ作成より先に終わると、結果を届ける先が無く一覧が空のままになる
（そして移動すると直るので、原因が分かりにくい）。`UiDispatcher` を「常にキューへ積む」
設計にして、`Attach` で掃き出すことで塞いだ。

### 選択の控えは「変更の前」でなければ意味がない（BUG-017）

第 1 段では、行が動く操作の前後で選択名を控えて付け直す処理を入れていたが、
**控えるタイミングを間違えていた**。モデルが `_entries` を書き換えてからイベントを
発火していたため、ビューが選択行を読むときには

- 一覧（コントロール）が返す行番号 … **古い**並び
- `_model.Entries[index]` … **新しい**並び

という食い違いが起きていて、控えた名前が最初から別のファイルのものになっていた。
削除で 1 つ繰り上がるので、結果として「繰り上がってきたファイル」を選択し直していた。

書き換えの**直前**に発火する `EntriesChanging` を足して解決した。
オーナーデータの一覧を扱う限り、**コントロールとモデルの並びが一致している瞬間**にしか
選択を名前へ翻訳できない、という制約は今後も効いてくる。

### `LVM_SETITEMCOUNT` はその場で呼び返してくる

行数を伝えるメッセージは、戻る前に `LVN_GETDISPINFOW` を同期的に呼び返す。
**配列の差し替えを先に済ませてから**行数を伝えないと、古い配列を新しい行数で読みに行く。
一覧へメッセージを送っている間はロックを取らない、という原則も同じ理由による。

## 設計との差異

なし（第 1 段時点）。

### 「例外が飛ぶはず」を前提にした分岐は、飛ばないことがある（BUG-020）

`DirectoryInfo.EnumerateFileSystemInfos()` は、**開こうとしたフォルダ自身が読めないとき
例外ではなく 0 件を返す**。`catch (UnauthorizedAccessException)` を書いてあっても
そもそも例外が飛ばないので、「0 件の成功」＝空フォルダとして表示されていた。

**1 回目の修正は外していた。**`EnumerationOptions.IgnoreInaccessible = false` を指定すれば
例外になると考えたが、この設定が効くのは**列挙中に出会う下位の項目**だけで、
対象フォルダ自身のオープン失敗には作用しない。確認側が `FindFirstFileW` の戻り値
（`ERROR_ACCESS_DENIED`）まで測ってくれて決着した。

いまは**列挙が 0 件だったときだけ** `FindFirstFileW` で直接確かめている。
0 件のときしか呼ばないので、通常のフォルダ表示にコストは乗らない。

`EnumerationOptions` の明示自体は残す。`AttributesToSkip = 0`（隠し・システムを
除外しない）は仕様上必要で、既定に頼ってよい値ではないため。

### 属性の変化も監視する（薄色表示の実態合わせ）

監視は「項目の増減・改名のみ」で始めたが、それだと**表示中に属性を変えても薄色にならない**。
確認側が `attrib +h` で試したときに差が出なかったのはこれが原因と見ている。

`NotifyFilters.Attributes` を足し、**薄色かどうかが変わったときだけ**その行を
同じ位置で差し替えるようにした。ファイルへの書き込みでもアーカイブ属性が立って
通知が来るので、足切りを入れないと無駄な描き直しが続く。行は動かないので、
「並べ替えを走らせない」という約束は保たれる。
