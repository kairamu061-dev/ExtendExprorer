# BUG-048: 遷移中は「行の名前」と「遷移先のパス」が混ざる（二重のパス／別フォルダの削除）

- **State**: Fixed
- **Reported**: 2026-10-20（利用者）
- **Area**: `ViewModels/FileListViewModel`（`Path` と `_entries` の更新時点）/ `UI/FileListView`

## Summary

フォルダをダブルクリックして**画面が切り替わる前に同じ行をもう一度ダブルクリック**すると、
**同じフォルダ名を 2 階層ぶん重ねたパス**（`D:\写真\写真`）を開こうとする。

**★ 同じ原因で、`Delete` が別のフォルダのファイルを消し得る。**
利用者の報告は「二重のパス」だけだが、調べたところ**選択からパスを組み立てる場所が
7 か所あり、そのどれもが同じ組み合わせを読んでいた**。削除・切り取り・貼り付け・
右クリック・持ち出し（ドラッグ）が同じ窓の中にある。

## Reproduction

1. 列挙に時間のかかるフォルダ（`D:\インストーラー` など）を開く
2. その中のフォルダの行を**ダブルクリック**する
3. **一覧が切り替わる前に**、同じ場所をもう一度ダブルクリックする
4. → アドレスが `D:\インストーラー\{名前}\{名前}` になり、「パスが見つかりません」になる

**削除の側（こちらは未実機・推測）**

1. `A\report.txt` と `B\report.txt` が両方ある状態にする
2. `A` を表示し、`report.txt` を選ぶ
3. `B` へ移動し、**一覧が切り替わる前に** `Delete` を押す
4. → 消えるのは **`B\report.txt`**（画面に出ているのは `A` の行）

## Expected

- 行から実パスを作るときは、**その行が属するフォルダ**を使う
- 遷移中の 2 回目のダブルクリックは、**1 回目と同じフォルダ**を開く（重ねない）
- 履歴に**同じパスが連続して積まれない**

## Cause

**`Path` と `_entries` は、別の時点で更新される。**

```
Load(B)  ── Path = B        ← 同期。アドレス欄はすぐ変わってほしいので、これは正しい
            （ここでメッセージは回り続ける。列挙は await の向こう）
Apply(B) ── _entries = B の行   ← あとから届く
```

**その間に入った操作は、`Path`（＝ B）と `_entries`（＝ A の行）を混ぜて読む。**

| 場所 | 読んでいた組 | 混ざると何になるか |
|---|---|---|
| `FileListViewModel.PathOf` | `Path` ＋ 行の名前 | ★ **二重のパス**（報告された症状）。ダブルクリックと改名の確定 |
| `FileListView.SelectedPaths` | `Path` ＋ 選択の名前 | ★ **`Delete` / `Ctrl+C` / `Ctrl+X` が別フォルダに当たる** |
| `FileListView` `folderAtRow` | `Path` ＋ 行の名前 | 落とし先が存在しないフォルダになる |
| `FileListView` `currentFolder` | `Path` | 落とし先が**見えていないフォルダ**になる |
| `FileListView.OnRightClick` | `Path` ＋ 行の名前 | 別フォルダの項目のメニューが出る |
| `FileListView.OnBeginDrag` | `Path` ＋ 選択の名前 | **別フォルダのものを持ち出す** |
| `FileListView` の `LVN_GETDISPINFO` | `Path` ＋ 行 | 絵が合わない（実害は小さい） |
| `MainWindow` の貼り付け | `ActiveList.Path` | 貼り付け先が**見えていないフォルダ**になる |

**`StillShowing`（監視の差分適用）も同じ組だった**が、こちらは `Path` と比べて
**取りこぼす**側に倒れていた（間違って当てることはない）。同じ不変条件なので揃えた。

## Fix

**`EntriesPath` を足した。**「いま並んでいる行が、どのフォルダのものか」。
`Apply` / `ApplyDrives` で `_entries` と**同じ時点で**書く。

- `Path` は**これから見せる先**（アドレス欄・タイトル・履歴・フォルダ別の並び設定）
- `EntriesPath` は**いま並んでいる行の持ち主**（行から実パスを作る・落とし先・メニュー・持ち出し）

`PathOf` は `EntriesPath` が空なら `null` を返す（最初の `Apply` が来るまで何も開かない）。

あわせて `Navigate` が**同じパスを連続して履歴に積まない**ようにした。
2 回目のダブルクリックは同じフォルダを開き直すだけになり、`戻る` が空振りしない。

  （**行が A・`Path` が B の状態を組んで、A のパスが返ることを確かめる**）

## 残っている危険

**`Delete` が別フォルダに当たる経路は、実機で踏んでいない。**
直したあとに踏めない（直っているので）ので、**旧ビルドで対照を取る**必要がある。
E-81 がそれ（**`A\report.txt` と `B\report.txt` を用意して旧ビルドで試す**）。

## 振り返り

**非同期にした時点で、「今の状態」は 1 つの変数では表せなくなっていた。**
`Path` に 2 つの意味（行先・現在地）を持たせたまま非同期にしたのが入口で、
BUG-040 の `isReload` と**同じ形の誤り**——
**1 つの比較で 2 つの問いに答えようとした**。

> **非同期にしたら、対になる状態は対で更新する。**
> 片方だけ先に書くなら、もう片方を読む場所を全部数えてからにする。
