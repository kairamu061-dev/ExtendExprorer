## 実機でしか確かめられないもの（手の往復に残す）

`UI/` と `Interop/` のほぼ全部。**人がやる**理由を添える。

| 対象 | なぜ自動化しない |
|---|---|
| 描画・描き残し | **矩形が正しくても画素が古いことがある**（BUG-037）。`RedrawWindow` との画素差で見る |
| 入力（クリック・キー・ドラッグ） | 合成入力は本物と違う道を通る。**合成の `ZoneId=3` が実物と違った**実例あり |
| シェルとの境界 | 他社のシェル拡張が**自分のプロセスの中で動く**。環境ごとに違う |
| メモリ実測 | 外から測った値でしか意味が無い（`Ctrl+Shift+G` の生存数と併せて読む） |
| インストール・アンインストール | レジストリとスタートメニューに書く。**戻し方まで依頼書に書く** |
| ネットワークの不在・切断 | **この PC では踏めない**（BUG-044 が保留のまま） |

## 判定に使う道具

**アプリ自身に数字を言わせる**のが基本（`--diag`）。推測の代わりに測定を置く。

| 仕組み | 何を分ける |
|---|---|
| `Diagnostics.Write`（`--diag` のときだけ） | 「起きたか」ではなく「何回・何 ms・どの項目か」 |
| `LiveObjects`（`Ctrl+Shift+G`） | **漏れ**と**まだ回収されていないだけ**。外から測ったメモリでは区別が付かない |
| `[icon] 0 枚の帯を並べた（起きてはいけない）` | **起きない前提**の仕掛け。鳴ったら構造が戻った合図 |
| 行の「形」での差分 | 順番と件数は揺れるので、**文字列と数字の位置**で突き合わせる |

> **診断は自分の仕事の証明にしかならない。**
> 利用者が見るもの（絵・画面・時間）を期待値に置き、診断はその裏取りにする——
> `F5` で絵が変わらないのに `裏で引いた=12` と出ていた回がある。

## ローカルにコンパイラが無いまま試験を足すとき

**この環境に .NET SDK は無い。**試験の構文の誤りは **CI でしか分からず、1 往復かかる。**
**実際に踏んだものだけ**を挙げる（増やすのは踏んでから）。

### 実際に踏んだもの

| 踏んだもの | 症状 | 出す前に確かめる |
|---|---|---|
| ★ **日本語のメソッド名に空白**（**2 回**） | `CS1002: ; expected` | `grep -rn "public void .* .*(" tests/ --include=*.cs` が**何も出さない**こと |

> ★ **2 回目を踏んだのが問題。**1 回目（`Ctrl_と_Shift_が同時なら Ctrl が勝つ`）で直したのに、
> **「気をつける」しかしていなかった。**
> **確かめる手を書いておかないと、同じ所をもう一度踏む。**

### 踏んでいないので書かないこと

**この節に「たぶん危ない」を足さない。**一度、**コレクション式を `Assert.Equal` に渡すと
オーバーロードが決まらない**と書きかけた。**確かめたら、既存の `ProgramArgsTests` が
同じ書き方で通っていた**（相手側が `string[]` なので型が決まる）。

> **「危なそう」を「踏んだもの」の表に混ぜると、表そのものが信用できなくなる。**
> 依頼書で「測った / 推測」を分けるのと、まったく同じ規則をここにも当てる。
