# BUG-052: 並べ替えると、選んでいた行が画面から外れる

- **State**: Fixed
- **Reported**: 2026-10-25（検証セッション・§3.3。**E-147 の不合格**）
- **Area**: `UI/FileListView.OnEntriesReset` / `RestoreSelection`

## Summary

行を選んで**見出しをクリックして並べ替える**と、**選んでいた行が画面に出ていない。**
代わりに**「並べ替える前の行番号」のあたり**が見える位置まで送られている。

## Reproduction

1. 2001 行のフォルダを**先頭行 45** までスクロールする
2. **49 行目**（`b0049`）をクリックして選ぶ
3. 見出し「名前」をクリックする

実測（新旧とも同じ値・画面写真も添付されている）:

| 操作 | 先頭行 | 選択行 | 選んだ行が見えるか |
|---|---|---|---|
| 選んだ直後 | 45 | 49 | 見える |
| 「名前」1 回目（降順に） | **45**（動かない） | 1951 | ★ **見えない** |
| 「名前」2 回目（昇順に） | **1912** | 49 | ★ **見えない** |
| 「名前」3 回目（降順に） | **49** | 1951 | ★ **見えない** |

## Expected

**選んだ行が見えたまま**（エクスプローラーと同じ）。

## Measured / Inferred

| | 測った（根拠） | 推測（何が分かれば決まるか） |
|---|---|---|
| 症状 | ★ **検証セッションが実測**（2026-10-25）。`LVM_GETTOPINDEX` と `LVM_GETNEXTITEM` で読み、**画面写真でも確認**（`e147_after1.png` に `b0049` が無い）。値は 25ms 以内に決まり、2 秒見ても変わらない | — |
| 原因 | ★ **ソースから確定。**`RestoreSelection` は `LVIS_SELECTED` を**付けるだけ**で、**そこへスクロールしていない**。一覧の側は「付け直す前に見ていた場所」に留まる | **なぜ 1912 や 49 に落ち着くか**の細かい理屈（一覧が `LVM_SETITEMCOUNT` の時点で古い焦点を見せようとしている、と読める）は**追っていない**。直すのに要らない |
| 影響 | ★ **旧 `fc537db` でも同じ数字**＝**BUG-051 の修正で出たものではない。前からあった** | いつから入っていたかは追っていない |

## Cause

**`bool keepSelection` 1 つに、2 つの問いを兼ねさせていた。**

| 入れ替わり方 | 選択を引き継ぐか | どこを見せるか |
|---|---|---|
| 別のフォルダへ移動 | いいえ | **先頭**（BUG-051） |
| 同じフォルダの読み直し（`F5`・監視） | はい | **動かさない**（飛ばされると困る） |
| **並べ替え** | はい | ★ **選択が見える位置**（行番号が付け直されている） |

**後ろ 2 つは「選択を引き継ぐ」が同じで、「どこを見せるか」が違う。**
bool では**区別できなかった。**

> **BUG-040 の `isReload` と同じ形。**
> **1 つの値で 2 つの問いに答えようとすると、片方が必ず間に合わなくなる。**

## Fix

`ResetKind`（`Navigate` / `Reload` / `Reorder`）を足して、
`EntriesReset` の引数を `bool` から差し替えた。

- `Navigate` → 選択を捨て、**先頭へ**（BUG-051 の挙動そのまま）
- `Reload` → 選択を引き継ぎ、**位置は動かさない**
- `Reorder` → 選択を引き継ぎ、**いちばん上の選択行が見える位置まで送る**

`RestoreSelection` が**付け直したいちばん上の行**を返すようにし、
`Reorder` のときだけ `LVM_ENSUREVISIBLE` を送る。
**`LVIS_FOCUSED` は付けない**——枠が飛ぶ（BUG-042 で同じ所を踏んでいる）。
