# BUG-056: 一覧が差し替わる直前の中クリックが、差し替え後の行に当たることがある

- **State**: Closed（**修正しない**・2026-11-23 利用者の判断）
- **Reported**: 2026-11-23（verification session・`確認依頼_フォルダの中クリックで新しいタブ` の V-04）
- **Area**: file-list / tabs（`src/ExtendExprorer.Win32/UI/FileListView.cs` の `OnMiddleDown` / `OnMiddleUp`）

## Summary

遷移を始めてから約 60ms 後に中クリックした回で、遷移中としても入れ替わりとしても断られなかった。
その中クリックは**差し替え後の一覧の 1 行目**（`w000001`）として処理され、新しいタブが開いた。
押した瞬間に画面に出ていたのが古い一覧なら、利用者が見ていない行のタブが開いたことになる。

## Reproduction

1. `D:\eetest\V`（7 件）を表示し、アドレス欄に `D:\eetest\W2`（フォルダ 10 万個）を入力する
2. カーソルを `fb` の行に置き、`Enter` を押して 60ms 待ってから、中ボタンを押して 40ms 後に離す
3. 診断に `[list] 中クリック … → 新しいタブ D:\eetest\W2\w000001` が出て、タブが 2→3 になる

この形で起きたのは 1 回。`Enter` から 0〜30ms 後の 6 回は `遷移中なので開かない`、15ms 後の 1 回は `入れ替わったので開かない` で断られている。

## Expected

古い一覧が画面に出ている間に押した中クリックは開かない（tabs 仕様 8-4。2026-10-23 のご要望「遷移中のクリックは無視したい」）。

## Measured / Inferred

| | 測った（根拠） | 推測（何が分かれば決まるか） |
|---|---|---|
| 症状 | 差し替え後の行名でタブが開いた。押す直前に `SendMessage` で読んだ件数は 7（古い一覧）だった（フィードバック §2 V-04） | **押した瞬間に画面が古い一覧だったか**は測れていない。件数 7 は証拠にならない（`SendMessage` での読み取りと、行列に入ったクリックの処理の順は保証されない） |
| 原因 | 差し替えは `UiDispatcher.Post`（`PostMessageW`）で UI スレッドへ届く（`UiDispatcher.cs:46`） | `GetMessage` は**ポストされたメッセージを入力メッセージより先に**取り出す。そのため、古い一覧の上で押されて行列に入っていた `WM_MBUTTONDOWN` が、差し替えの**後**に処理されたと考えている。押下も解放も差し替えの後に処理されたなら、`_generation` は変わらず `Navigating` も下りているので、どちらの守りにも掛からない。メッセージの時刻（`GetMessageTime`）と差し替えた時刻を記録すれば確かめられる |
| 影響 | 再現した 1 回でタブが 1 枚余分に開いた（裏で開くだけ。ファイルは起動しない） | **ダブルクリック（`Activate`）にも同じ隙間がある**と考えている（BUG-049 の守りも、1 打目の**処理**の時点の世代で比べている）。ダブルクリックではファイルが起動しうるので、影響はこちらの方が大きい。未確認 |
