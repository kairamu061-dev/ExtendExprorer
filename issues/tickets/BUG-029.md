# BUG-029: ドラッグ中にプロセスが落ちる（0xc0000409・記録は残らない）

- **State**: Open（原因未特定・切り分け中）
- **Reported**: 2026-08-30
- **Area**: win32-migration / drag-drop / `src/ExtendExprorer.Win32/UI/ListDropTarget.cs`

## Summary

エクスプローラーからファイルをドラッグしてアプリのウィンドウに入れると、
**ドロップする前にプロセスが消える**。`DragEnter` と最初の `DragOver` は成立していて
（ドロップ効果の「＋ コピー」が出る）、**2 回目のマウス移動で落ちる**。

`error.log` は 1 行も出ない。

## Reproduction

1. アプリと、別フォルダのエクスプローラーを並べる
2. エクスプローラーでファイルを 1 つ掴み、アプリの一覧の上へ持っていく
3. **アプリの上で 2 回ほどマウスを動かす** → 落ちる（ドロップは不要）

| 段階 | 生存 |
|---|---|
| ウィンドウに入る（`DragEnter`） | ○ |
| 入った位置で止まる（最初の `DragOver`） | ○ |
| そこから 1 回目の移動 | ○ |
| **2 回目の移動** | **✕** |

クラッシュの署名は 7 回すべて同一。

```
Faulting module name: unknown
Exception code: 0xc0000409     ← .NET の fail-fast
```

## Expected

落ちないこと。

## Cause

**ドラッグ元のオブジェクトの「包み」を、ファイナライザ任せにしていた。**

`DragEnter` で受け取る `IDataObject` は**相手のプロセス・相手のアパートメント**の
オブジェクト。これを `ComWrappers.GetOrCreateObjectForComInstance` の既定
（`CreateObjectFlags.None`）で包むと、包みの解放は**ガベージコレクションの
ファイナライザ**に委ねられる。

ファイナライザは**別のスレッド**で走るので、そこからの解放は成り立たない。
**ファイナライザで例外が出るとランタイムが fail-fast する**（`0xc0000409`）。
これは `try`/`catch` の外側の出来事なので、**こちらの記録には何も残らない**
——「`error.log` が 1 行も出ない」ことと符合する。

2 回目の移動で落ちるのは、そのころに最初のガベージコレクションが走るため。

> 断定はできていない。ただし「記録が残らない」「モジュールが unknown」
> 「回数に再現性がある」は、この筋で説明が付く。

## 試したこと（1 回目・`c4dd21a`）— **外れ**

「包みの解放がファイナライザ任せ」という見立てで `UniqueInstance` ＋ `Dispose` に変えた。
**落ち方は変わらなかった**（同一署名で 6 件）。むしろ、

- 前のビルドでは出ていた「＋ コピー」のドロップ効果が**出なくなった**
- `[drop] DragEnter` のログが**1 度も出ない**（アプリが生きている間に読んでも無い）

という差が出た。**この見立ては外れ。**

## いま分かっていること

| 条件 | 結果 |
|---|---|
| ドラッグせずにアプリの上でマウスを 20 回動かす | 落ちない |
| ドラッグしたまま、アプリに入らず 15 回動かす | 落ちない |
| **ドラッグしたままアプリの上へ入って動かす** | **1〜2 回目で落ちる** |

「ドラッグしている」かつ「アプリの上」の両方が揃ったときだけ落ちる。
`RegisterDragDrop=0x00000000` は出るが、`DragEnter` のログは出ない。
`error.log` も出ない（＝マネージドの `try`/`catch` の外）。

fault offset は 2 つのビルドで**同一**（`0x00007ff9bcf0628f`）。

## 2 回目（`30de076`）— 判定材料を増やし、危ない形を 2 つ外した

**まだ「直した」ではない。**次の 1 往復で決着させるための手当て。

1. **入口・出口のログ**を 4 つの呼び出しすべてに。`DragEnter` の入口は
   **何よりも先に**書く。これで「呼ばれていない」と「呼ばれた中で落ちている」が分かれる
2. **相手の `IDataObject` に包みを立てるのをやめた。**呼ぶのは `GetData` 1 つだけなので
   vtable から直に呼ぶ。ソース生成の一式を経路から外す
3. **ドロップ先の強調を、他人のモーダルループの中から一覧へ書き込まない形にした。**
   `UiDispatcher` でいったん抜けてから当てる。改名・コンテキストメニューで
   すでに立てていた原則（他人のモーダルループの中で入れ子の処理をしない）を、
   ここにも適用していなかった

- **Commit**: `30de076`

## Notes

コンテキストメニュー（`ShellContextMenuService`）も同じ形で包みを作っている。
そちらはメニューが閉じるまでの短い間だけで、実績もあるため今回は変えていないが、
**同じ危険はある**。ここで落ちるようなら次はそちらも見る。
